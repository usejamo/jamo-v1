### Notes

**AC-4 test passed immediately (not a blocking RED).** The test validates `computeTerminalWrites` with `originating_action` pre-stamped on `toolData` — the pure function already handles this correctly. The implementation work (the two-step lookup in AIChatPanel Site 2) is what actually stamps the value before enqueueing. The RED commit was made with the un-skipped test; the GREEN commit added the AIChatPanel Sites 1 & 2.

**onSectionFocusChange used for focus (D-01 cond 2).** Plan specified `setActiveSectionKey(action.section_key)` but `activeSectionKey` is a prop (not local state) — the correct call is `_onSectionFocusChange?.(action.section_key)` which is the prop callback. This is the correct mechanism and achieves identical effect.

**onSkip wired inline (not as named function).** `onStopWalkthrough` is an inline callback inside `WalkthroughProgress`, not a named function ref accessible at the AskUserCard render site. Duplicating the exact body (same 3 lines) at the render site follows PATTERNS.md guidance ("if onStopWalkthrough is already a named function, pass it directly; otherwise inline the EXACT discard body").
