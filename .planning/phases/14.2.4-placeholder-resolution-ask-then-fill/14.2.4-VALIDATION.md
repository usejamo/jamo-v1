### Load-bearing invariants (Wave 0 unit stubs)

- **(a) Enum sync** — `PendingActionSchema.safeParse({…, cta_tool:'ask_user'})` succeeds on edge; `ActionItemCtaTool` accepts `'ask_user'` on client. One Deno test + one vitest type-level test.
- **(b) active_task shape identity** — the needs-value `ask_user` dispatch produces an object passing `ActiveTask` constraints with `status:'active'`, `stage:'gathering_inputs'`, and all 10 required fields — structurally identical to `set_focus`'s write. Vitest unit test against an extracted pure shape-builder.
- **(c) No resolved_items write on abandon/defer** — `computeTerminalWrites` with `originating_action: null` produces zero writes; verify coverage extends to the `onSkip` path (no edits created → no terminal state).
- **(d) Snapshot survival** — `active_task.originating_snapshot` set on ask dispatch; `takeSnapshot` reads it from `active_task` at `propose_edit` arrival (not the in-memory Map keyed `section_key:ask_user`). Assert `toolData.originating_action` non-null after the `propose_edit` event.
- **(e) Partial-resolution re-surface** — `buildResolvedItemEntry({accepted:N, rejected:0, stale:0})` sets `user_action:'fixed'`; `rebuildFilterSet` does NOT hard-suppress; remaining placeholders re-surface. Add an ask-then-fill-variant assertion to existing resolved-items tests.
