## WorkspaceSection HTML field (W5 closure)

**Verified field name:** `content`

**Source file:** `src/types/workspace.ts`, line 96 — `SectionEditorState.content: string`

**Note on naming:** This codebase does NOT use a `WorkspaceSection` type. The canonical section shape is `SectionEditorState` (declared in `src/types/workspace.ts`), which holds the TipTap-serialized HTML in the field `content`. The workspace state shape is `WorkspaceState` (line 145) which contains `sections: Record<string, SectionEditorState>`.

**Consumers that read/write this field today:**
- `src/types/workspace.ts:96` — declaration (`content: string`)
- `src/context/SectionWorkspaceContext.tsx:25` — reducer case `UPDATE_CONTENT` mutates `sections[key].content`
- `src/types/workspace.ts:115` — `WorkspaceAction` variant `{ type: 'UPDATE_CONTENT'; payload: { section_key, content } }`

**Guidance for Plans 04 + 05:**
- Plan 04 client read: `workspaceState.sections[section_key].content`
- Plan 05 edge function read: `s.content` (where `s` is the section row from `proposal_sections` — confirm parity at the DB layer in Plan 05; `proposal_sections` has historically used `content TEXT` for serialized HTML)
- Replace all `.body` placeholders with `.content`
