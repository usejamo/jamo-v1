## Edge function section iteration (W3 closure)

**Variable name:** `sections`
**Content field:** `content`

**Source:** Request body validated via `RequestSchema` (lines 66–75):
```typescript
sections: z.array(z.object({
  key: z.string(),
  title: z.string(),
  content: z.string(),
})).optional().default([]),
```

Then bound to local `sections` variable at line 127 (`let sections: Array<{ key: string; title: string; content: string }>`) and assigned at line 139 (`sections = parsed.data.sections`).

**Per-section hash computation (Plan 05 addition):**
```typescript
for (const s of sections) {
  sectionHashes[s.key] = await sha256Hex(s.content)
}
```

Confirms parity with W5 closure from Plan 01 (`SectionEditorState.content`): the client serializes TipTap HTML to the same `content` field name that the edge function receives in its request body. No DB-layer divergence — the edge function does not read `proposal_sections` directly; sections arrive already-serialized via the client request body.

## Exported `buildResolvedBlock` signature

```typescript
export function buildResolvedBlock(
  annotatedResolved: AnnotatedResolvedItem[],
): string
```

Where `AnnotatedResolvedItem = ResolvedItem & { content_status: 'content_unchanged_since_action' | 'content_changed_since_action' }`.

Returns `''` when array is empty (no block injected). Returns a multi-line string containing the RESOLVED_ITEMS header, JSON-serialized entries, 5 instructions, and 2 worked examples when non-empty.

Located in `supabase/functions/analyze-proposal-gaps/index.ts`. Plan AC requires the literal grep `export function buildResolvedBlock` to match in this file — confirmed (`grep -c` returns 1).

## Approach: A (keep in index.ts) vs B (extract to prompt.ts)

**Chosen: Approach A.** Plan acceptance criterion requires `grep -c "export function buildResolvedBlock" supabase/functions/analyze-proposal-gaps/index.ts` returns 1. Approach B (separate `prompt.ts` + re-export) would not match the grep. The trade-off — Vitest needing to import `index.ts` which calls `Deno.serve(...)` at module level — was resolved via a sidecar Vitest config + Deno polyfill (`vitest.supabase.config.ts` + `setup.ts`). Single source of truth for the prompt string preserved.
