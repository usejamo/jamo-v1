## Substitution locus + tool contract

### Q: Where do locate + substitute run?

| Option | Description | Selected |
|--------|-------------|----------|
| Client-side deterministic | Model emits routing only; browser walks live TipTap docs, locates by id, validates, substitutes, materializes per section. No new edge endpoint. | ✓ |
| Edge endpoint | New/extended edge fn does locate+substitute server-side; must re-parse HTML, deploy, adopt 14.3 auth helper. | |
| Hybrid (edge locate, client apply) | Splits deterministic op across network for little gain. | |

**User's choice:** Client-side deterministic.

### Q: How does the model express bulk intent — the tool contract?

| Option | Description | Selected |
|--------|-------------|----------|
| New dedicated tool | `substitute_placeholders(value, targets:[{section_key, placeholder_id, decision, skip_reason?}])`; leaves propose_edit untouched. | ✓ |
| Extend propose_edit | Widen to multi-target; mutates the proven single-section contract. | |

**User's choice:** New dedicated tool.
**Notes:** Tool carries classification, not edits (no after_html / generated content) — guardrail against generative find-replace. Client doc-walk is authoritative over the tool's targets (unresolvable id → skip+report). Unified skip channel: model skips + client skips → same reporting surface. Edge just registers + forwards through existing materialize path. Fan-out is the first real multi-section exercise of 14.3's per-section ghost guard — most likely bug seam.

## Granularity bridge + mark fate

### Q: How does a span-level fill become a reviewable ghost edit (pending edits anchor at paragraph granularity)?

| Option | Description | Selected |
|--------|-------------|----------|
| Paragraph-level replace | Resolve span → containing paragraph; emit standard replace PendingEdit with after_html = paragraph HTML with span content replaced. Reuses whole pipeline. | ✓ |
| New mark-granularity edit op | Anchor by placeholder_id, replace only the span; net-new decoration/materialize/anchor code. | |

**User's choice:** Paragraph-level replace.
**Notes:** Bulk edits are ordinary PendingEdits → fan-out + 14.3 guard treat them as normal. Edge case: multiple target placeholders in one paragraph → group by containing paragraph, compose all substitutions into one after_html, emit ONE PendingEdit per paragraph (naive one-per-placeholder collides on same paragraph_id). change_summary = "filled <label> placeholder".

### Q: When a substitution is accepted, what happens to the amber placeholder mark?

| Option | Description | Selected |
|--------|-------------|----------|
| Strip mark → resolved plain text | Value replaces placeholder as normal text, data-placeholder-id mark removed; no longer flagged. Baked into after_html (aiApplied bypasses resolutionPlugin). | ✓ |
| Keep mark on filled text | Span stays amber / flagged; confusing, diverges from manual-edit resolution. | |

**User's choice:** Strip mark → resolved plain text.

## Classifier execution

### Q: Where does single-value-vs-multi-part classification run?

| Option | Description | Selected |
|--------|-------------|----------|
| Folded into main chat turn | Existing chat model classifies each target as it emits substitute_placeholders; zero extra round-trips; bias-to-skip in tool description + system prompt. | ✓ |
| Separate cheap Haiku pre-pass | Dedicated Haiku classifies before main turn; adds a round-trip, splits logic, duplicates context. | |

**User's choice:** Folded into main chat turn.
**Notes:** One turn in, deterministic execution out — no second model call in the path. Classification-not-generation guardrail holds even when folded: model emits only decisions + reasons, never edit content. Bias-to-skip-on-uncertainty encoded in tool description + system prompt.
