### `src/editor/placeholders/substitute.ts` (NEW — pure utility, transform)

**Analog:** `src/lib/placeholderHtml.ts` (tiny pure HTML util) + the mark serialization contract in `PlaceholderMark.ts:114-137`.
**Planned exports (RESEARCH §Finding 1, Pattern 1):** `resolvePlaceholderTarget`, `groupTargetsByParagraph`, `buildSubstitutedParagraphHtml`.

**Analog pattern** — a pure module that takes strings and returns HTML strings, no editor instance (`src/lib/placeholderHtml.ts:1-6`):
```ts
import { escapeHtml } from './escapeHtml'

export function placeholderPatternToSpan(label: string, id: string): string {
  const escaped = escapeHtml(label.trim())
  return `<span data-placeholder-id="${id}" data-placeholder-label="${escaped}">${escaped}</span>`
}
```
This confirms the serialized span shape the new module must PARSE: `<span data-placeholder-id="…" data-placeholder-label="…">…</span>`.

**Core recipe to build (RESEARCH Pattern 1, verified against `PlaceholderMark.ts:114-129` + `SectionEditorBlock.tsx:186-189`):**
```ts
export function buildSubstitutedParagraphHtml(
  paragraphOuterHtml: string,   // full '<p data-id="uuid">…<span data-placeholder-id="p1" …>label</span>…</p>'
  placeholderIds: string[],     // ALL target spans in THIS paragraph (D-09 grouping)
  value: string,                // literal user-supplied value
): string {
  const doc = new DOMParser().parseFromString(paragraphOuterHtml, 'text/html')
  const para = doc.body.firstElementChild!            // the <p>/<li>/<td> block — preserves data-id
  for (const id of placeholderIds) {
    // Pitfall 3: CSS.escape may be absent in happy-dom — iterate + getAttribute compare instead of a computed selector
    const span = Array.from(para.querySelectorAll('[data-placeholder-id]'))
      .find((el) => el.getAttribute('data-placeholder-id') === id)
    if (!span) continue
    span.replaceWith(doc.createTextNode(value))       // D-10: strip mark + insert literal text node
  }
  return para.outerHTML                               // MUST be the whole <p data-id> element
}
```
**Hard constraints (from analogs):**
- `after_html` MUST be the entire `<p data-id="…">…</p>` — accept does `deleteRange({from,to})` then `insertContentAt(from, after_html)` over the whole paragraph node (`SectionEditorBlock.tsx:186-189`). A bare inner fragment loses the anchor.
- Insert value as a plain text node (span removed) — the `aiApplied` transaction bypasses `resolutionPlugin` (`PlaceholderMark.ts:35`), so mark-strip must be baked in here (D-10).
- Preserve the paragraph `data-id` — `ghostContentLeakDetected` allows it because `id === edit.paragraph_id` (own-anchor exception, `decorations.tsx:27`).
- Pure/deterministic: no timestamps/UUIDs inside → byte-identical on repeat (SPEC R3).
- `resolvePlaceholderTarget`: walk up from the matched span to the nearest ancestor carrying `data-id`; no `data-id` ancestor ⇒ return null ⇒ caller makes it a client skip (D-04, Pitfall 2).

## Shared Patterns

### The synthetic `PendingEdit` shape (authoritative — the one thing a substitution must get exactly right)
**Source:** `src/types/workspace.ts:48-91`; validated by `materializePendingEdits` (`SectionEditorBlock.tsx:397-419`).
**Apply to:** every edit the fan-out builds. A clean synthetic paragraph-replace MUST set:
```ts
{
  id: `${bulkMsgId}-${section_key}-${i}`,   // globally unique across the fan-out (Pitfall 4)
  paragraph_id: <containing block data-id>,  // MUST exist in the section doc or it is dropped (:397-410)
  section_key,
  operation: 'replace',
  before_html: <current paragraph HTML>,     // optional/informational — include for parity
  after_html: <full <p data-id>…</p> with span filled + mark stripped>,  // D-07/D-10
  change_summary: `filled <label> placeholder`,   // D-07 — makes the ghost self-describing
  resolution: 'pending',
  message_id: bulkMsgId,
  change_index: i,                            // per-paragraph order
  created_at: new Date().toISOString(),
}
// anchor_hash is added BY materialize (:427-436); anchorFrom/anchorTo are runtime-only — do NOT set.
```

### Ghost-isolation guard (the D-06 seam — per-section, stateless)
**Source:** `ghostContentLeakDetected` invoked inside `materializePendingEdits` (`SectionEditorBlock.tsx:438-443`); own-anchor exception at `decorations.tsx:27`.
**Apply to:** the fan-out. Guard runs per section on `editor.getHTML()` + only that section's edits. Passes because each edit's only declared block `data-id` equals its own `paragraph_id` anchor. There is NO cross-section registry to false-positive. Real failure mode = D-09 (two spans in one paragraph → two competing replaces on one `paragraph_id`) → MUST group by paragraph before building edits. Test a 2-section fan-out explicitly (SPEC/D-06).

### Reducer reuse (no change)
**Source:** `SectionWorkspaceContext.tsx:207-225` (`SET_PENDING_EDITS` merges by `message_id`, preserves N sections concurrently) + `:298-322` (`BATCH_ACCEPT_PENDING_EDITS` marks pending→accepted for the given ids, silently skips non-pending).
**Apply to:** all fanned-out sections. State shape `sections: Record<section_key, { pending_edits }>` already holds N sections — no reshape needed. Confirm `SET_PENDING_EDITS` merge (`:214` filters `e.message_id !== message_id`) coexists with the shared `bulkMsgId` per section (it does — keyed per section_key).

### Honest failure reporting (SPEC R7, no silent failures)
**Source:** `formatEditApplyFailure` push at `AIChatPanel.tsx:604-611`; chat text derived from result at `:569`.
**Apply to:** every bulk run. Compose the one-liner client-side after reconciliation (D-15): full = "Substituted `<value>` in N sections."; partial = "Substituted in N, skipped M."; zero-match = "'`<target>`' isn't a fillable placeholder — nothing to substitute." (card suppressed).
