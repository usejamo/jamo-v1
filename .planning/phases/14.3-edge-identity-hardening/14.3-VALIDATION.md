## Validation Architecture (from RESEARCH.md)

Behaviors that MUST be validated (planner maps each to a task):

1. **JWT-derived identity** — each hardened function resolves `user_id`/`org_id` from `auth.getUser()` + `user_profiles` lookup, not the body.
2. **Body-tamper rejection** — a request whose body `user_id`/`org_id` differs from the JWT is served by the JWT identity (or rejected), never the body's.
3. **Internal-caller preservation (retrieve-context)** — the service-role internal caller (`chat-with-jamo/rag.ts`) still receives chunks for the passed `orgId`; only user-JWT calls are org-validated.
4. **chat-with-jamo regression** — an authenticated chat still lands `chat_sessions` writes after identity derivation is hoisted above the first DB read.
5. **401 on missing/invalid JWT** — user-authenticated surfaces reject unauthenticated calls consistently.
