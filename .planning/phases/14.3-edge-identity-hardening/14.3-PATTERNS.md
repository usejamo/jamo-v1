### Pattern B — Two-client identity derivation (the canonical copy target for the helper)

**Source:** `section-ai-action/index.ts:53-68` (cleanest two-client variant; `generate-proposal-section:418-439` is identical in shape).
```ts
// Resolve user and org from JWT
const authHeader = req.headers.get('Authorization')
const supabase = createClient(                       // service-role client — privileged writes
  Deno.env.get('SUPABASE_URL')!,
  Deno.env.get('SUPABASE_SERVICE_ROLE_KEY')!
)
const userClient = createClient(                     // anon + JWT — identity ONLY
  Deno.env.get('SUPABASE_URL')!,
  Deno.env.get('SUPABASE_ANON_KEY')!,
  { global: { headers: { Authorization: authHeader ?? '' } } }
)
const { data: { user } } = await userClient.auth.getUser()
const { data: profile } = user
  ? await supabase.from('user_profiles').select('org_id').eq('user_id', user.id).single()
  : { data: null }
const orgId: string | null = profile?.org_id ?? null
```
> **org_id is NOT in the JWT** — it always comes from the `user_profiles` lookup keyed by `user.id`. This is the single most important gotcha (documented `analyze-proposal-gaps:226-228`).

### Pattern C — Strict 401 guard (use in the helper, not the loose `user!` variant)

**Source:** `analyze-proposal-gaps/index.ts:203-224` — the exemplars are inconsistent on null-safety; **copy this guarded version**, not `generate-proposal-section`'s non-null `user!`.
```ts
const authHeader = req.headers.get('Authorization')
if (!authHeader) {
  return new Response(JSON.stringify({ error: 'Missing Authorization header' }),
    { status: 401, headers: { ...corsHeaders, 'Content-Type': 'application/json' } })
}
const supabase = createClient(supabaseUrl, supabaseAnonKey, {
  global: { headers: { Authorization: authHeader } },
})
const { data: { user }, error: authError } = await supabase.auth.getUser()
if (authError || !user) {
  return new Response(JSON.stringify({ error: 'Unauthorized' }),
    { status: 401, headers: { ...corsHeaders, 'Content-Type': 'application/json' } })
}
const userId = user.id  // Canonical identity — JWT-derived, not client-supplied
// then user_profiles.org_id lookup (guard null → 401/500, never pass null: Pitfall 5)
```

### Pattern D — Internal service-role caller detection (for `retrieve-context` branch only)

**Source (the caller that must be preserved):** `chat-with-jamo/rag.ts:41` sends the service-role key as bearer:
```ts
headers: {
  "Content-Type": "application/json",
  "Authorization": `Bearer ${Deno.env.get("SUPABASE_SERVICE_ROLE_KEY")}`,
},
body: JSON.stringify({ orgId, query, k_regulatory, k_proposal }),
```
Detection helper (`isInternalServiceRoleCall`) compares the bearer token to the env key — no new header, no new secret:
```ts
const token = req.headers.get('Authorization')?.replace('Bearer ', '')
if (token === Deno.env.get('SUPABASE_SERVICE_ROLE_KEY')) { /* INTERNAL: trust body orgId */ }
```
