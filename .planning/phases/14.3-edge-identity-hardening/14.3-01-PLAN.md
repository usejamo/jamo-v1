    2. `export function jsonError(status: number, message: string, corsHeaders: Record<string,string> = {}): Response` — the exact response shape used verbatim in every exemplar:

    3. `export async function getAuthedUserAndOrg(req: Request, corsHeaders: Record<string,string> = {}): Promise<{ userId: string; orgId: string }>` — Pattern B two-client + Pattern C STRICT guard. Build a service-role `supabase` client (URL + SUPABASE_SERVICE_ROLE_KEY) for the profile lookup and an anon `userClient` (URL + SUPABASE_ANON_KEY, `global.headers.Authorization = authHeader`) for identity ONLY:
    ```ts
    const authHeader = req.headers.get('Authorization')
    if (!authHeader) throw jsonError(401, 'Missing Authorization header', corsHeaders)
    const userClient = createClient(Deno.env.get('SUPABASE_URL')!, Deno.env.get('SUPABASE_ANON_KEY')!,
      { global: { headers: { Authorization: authHeader } } })
    const { data: { user }, error: authError } = await userClient.auth.getUser()
    if (authError || !user) throw jsonError(401, 'Unauthorized', corsHeaders)
    const supabase = createClient(Deno.env.get('SUPABASE_URL')!, Deno.env.get('SUPABASE_SERVICE_ROLE_KEY')!)
    const { data: profile } = await supabase.from('user_profiles').select('org_id').eq('user_id', user.id).single()
    const orgId = profile?.org_id ?? null
    if (!orgId) throw jsonError(401, 'No org for user', corsHeaders)   // Pitfall 5 — NEVER pass null org
    return { userId: user.id, orgId }
    ```
    Note in a comment: org_id is NOT in the JWT — it always comes from the user_profiles lookup keyed by user.id (PATTERNS Pattern B gotcha; analyze-proposal-gaps:226-228).
    Since `throw jsonError(...)` throws a Response, document that callers wrap `getAuthedUserAndOrg` in try/catch and, when the caught value `instanceof Response`, return it directly (this is how Wave 2 plans will consume it).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → edge function | Request body + Authorization header are attacker-controllable; only the JWT signature is trusted |
| edge function → edge function (internal RAG) | chat-with-jamo calls retrieve-context with the service-role key as bearer (trusted origin) |
| edge function → Postgres (RLS) | org isolation enforced at DB; helper must supply the correct org_id |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14.3-01 | Spoofing/Elevation | getAuthedUserAndOrg | mitigate | Identity from `userClient.auth.getUser()` (server-verified JWT), never body; org via user_profiles lookup keyed by verified user.id |
| T-14.3-02 | Elevation (confused deputy) | isInternalServiceRoleCall | mitigate | Compare bearer to SUPABASE_SERVICE_ROLE_KEY (unspoofable secret), not a client-settable header |
| T-14.3-03 | Information Disclosure | null org_id path | mitigate | Throw 401 when org_id is null (Pitfall 5) — never pass null into an org filter (would bypass scoping / violate NOT NULL) |
| T-14.3-04 | Tampering | jsonError leakage | accept | Generic 'Unauthorized'/'No org for user' messages; no user/org enumeration in error bodies |
</threat_model>
