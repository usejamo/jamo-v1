# Phase 14.3 Plan 02: Harden chat-with-jamo Identity Summary

**Hoisted JWT-derived `userId`/`orgId` (via shared `getAuthedUserAndOrg`) to the top of chat-with-jamo's try block, before the first `chat_sessions` read, and replaced all 9 body-identity use-sites (session filters, RAG scoping, compliance/set-focus calls) with the JWT-derived values — closing the primary cross-tenant impersonation vector.**

## Performance

- **Duration:** 18 min
- **Tasks:** 2/2 completed
- **Files modified:** 2

## Accomplishments

- Added `import { getAuthedUserAndOrg } from '../_shared/auth.ts'` and hoisted the derivation (with its required try/catch + `instanceof Response` return) to run immediately after the `user_message`/`target_section` guard — well before the first `.from('chat_sessions')` call.
- Removed `org_id`/`user_id` from the body destructure entirely (not merely unused) so no stray body-identity reference can compile silently. A code comment documents that the client may still send these fields (D-04 backward compat) but they are never read.
- Built one user-scoped `supabase` client (anon key + the same validated `Authorization` header `getAuthedUserAndOrg` used) immediately after identity derivation, and reused it for every subsequent `chat_sessions` read and write — eliminating the old headerless anon client on the first read (T-14.3-07) and the old duplicate late-built write client.
- Replaced every use-site per the plan's authoritative map: the active_task read/expire guard and filters (`if (proposal_id && userId)`, `.eq('user_id', userId)` x5), `fetchRagContext(orgId, ...)`, `handleCheckCompliance(..., orgId)`, and `handleSetFocus(..., orgId, session_id)`.
- Added two `ignore:true` Deno.test scaffolds to `test.ts` (matching this file's existing convention) documenting the REQ-1 body-tamper and no-regression behaviors, with a top comment pointing to 14.3-05 (RESEARCH.md Q6) as the live-validation owner.

## Decisions Made

- Consolidated the two previously-separate supabase client instantiations (headerless-anon read client at the old :110-118, and the late-built authed write client at the old :156-162) into a single client built once right after JWT derivation. This was a natural consequence of the plan's explicit requirement ("the first session read uses the authed client, not a headerless anon client") rather than a scope expansion — same import, same construction args, just built earlier and reused.
- Kept the non-null assertion `req.headers.get("Authorization")!` on the header re-read, since `getAuthedUserAndOrg` already throws a 401 Response if the header is absent — by the time this line runs, the header is guaranteed present.
