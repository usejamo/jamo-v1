# Phase 14.3 Plan 04: Harden salesforce-oauth-initiate/disconnect Summary

JWT-derived org_id now binds the CSRF signed state, oauth_pending row, and salesforce_connections lookup/delete/Vault-revoke in both Salesforce OAuth edge functions — closing cross-tenant CSRF-state and disconnect-hijack paths (T-14.3-13, T-14.3-14).

## What Was Built

**Task 1 — `salesforce-oauth-initiate/index.ts` hardened:**
- Imports `getAuthedUserAndOrg, jsonError` from `../_shared/auth.ts`.
- Body destructure renamed `org_id` → `body_org_id` (kept optional in the type); `is_sandbox` still read from the body unchanged.
- JWT org derived immediately after the secrets check, wrapped in the standard try/catch-and-return-Response pattern.
- A present `body_org_id` that differs from the JWT `orgId` returns `403 'org mismatch'` before any PKCE/state generation.
- `signState(orgId, nonce, consumerSecret)` and the `oauth_pending` insert (`org_id: orgId`) both now reference the JWT-derived org exclusively.

**Task 2 — `salesforce-oauth-disconnect/index.ts` hardened:**
- New import of `getAuthedUserAndOrg, jsonError` (this file previously had zero `_shared` imports).
- Body destructure renamed `org_id` → `body_org_id`.
- JWT org derived before the service-role client is built; a present `body_org_id` mismatch returns `403 'org mismatch'` before any connections lookup, Vault RPC, or delete runs.
- `.eq('org_id', orgId)` (select) and `.eq('org_id', orgId)` (delete) both use the JWT-derived org; the service-role client itself is preserved unchanged for the privileged Vault revoke/delete.

**Task 3 — test scaffolds:**
- `salesforce-oauth-initiate/test.ts` and `salesforce-oauth-disconnect/test.ts` created following the `retrieve-context/test.ts` convention: one active pure assertion per file exercising the "mismatched body org_id is never trusted, JWT org always wins" guard logic, plus two `ignore: true` integration scaffolds per file pointing to 14.3-05 as the live-validation owner (full request/response behavior needs a live Supabase auth server + Salesforce Connected App secrets / Vault, unavailable in this dev environment).

## Deviations from Plan

None — plan executed exactly as written. Both functions were confirmed user-authenticated-only per RESEARCH Q4 (`SalesforceConnection.tsx:68` and `:82`), so no internal-caller branch was needed (unlike 14.3-03's `retrieve-context`).
