### RLS: org-admin write policy on `organizations` (3 toggles)

**Analog:** `supabase/migrations/20260418000023_templates.sql`, `templates_insert_admin` (lines 47-53)

```sql
CREATE POLICY "templates_insert_admin" ON templates FOR INSERT
  WITH CHECK (
    org_id IS NOT NULL
    AND org_id = (SELECT org_id FROM user_profiles WHERE user_id = auth.uid())
    AND (SELECT role FROM user_profiles WHERE user_id = auth.uid()) IN ('admin', 'super_admin')
  );
```
**Adaptation required (no direct UPDATE analog exists):** this is INSERT-shaped; `organizations` needs an UPDATE policy. Per RESEARCH.md Pitfall 2, the ONLY existing write policy on `organizations` is `orgs_super_admin` (`ALL`, `role = 'super_admin'`) — a NEW policy is required, not a copy-paste of an existing organizations policy (none exists for org-admin). Copy the role-check subquery shape above into a `FOR UPDATE` policy scoped to `org_id = (SELECT org_id FROM user_profiles WHERE user_id = auth.uid())` — and per RESEARCH.md's "Don't Hand-Roll" table, prefer a dedicated RPC or column-scoped trigger guard over a blanket UPDATE policy so `plan`/`slug`/`is_active` aren't incidentally opened to org-admin writes.

### RLS/RPC: admin-gated write for `proposals.reference_override`

**Analog:** Same `templates_insert_admin` role-check shape (above). No existing `proposals` UPDATE policy has a role check (`proposals_update` is `org_id = get_user_org_id()` only, per RESEARCH.md Pitfall 3, live-verified via `pg_policies`).

**Recommended shape (RPC, per RESEARCH.md Open Question 2 recommendation, consistent with D-02's "express the rule once" RPC-heavy convention):**
```sql
CREATE OR REPLACE FUNCTION set_reference_override(p_proposal_id uuid, p_value boolean)
RETURNS void
LANGUAGE plpgsql SECURITY DEFINER SET search_path = public
AS $$
BEGIN
  IF (SELECT role FROM user_profiles WHERE user_id = auth.uid()) NOT IN ('admin','super_admin') THEN
    RAISE EXCEPTION 'not authorized';
  END IF;
  UPDATE proposals SET reference_override = p_value
    WHERE id = p_proposal_id
      AND org_id = (SELECT org_id FROM user_profiles WHERE user_id = auth.uid());
END;
$$;
```
This can be `plpgsql` (unlike the read-path match RPCs) since it is a single mutation, not a hot retrieval path bound by the `LANGUAGE sql` constraint that applies to `match_chunks_*_proposals`.
