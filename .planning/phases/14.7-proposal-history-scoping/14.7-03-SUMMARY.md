# Phase 14.7 Plan 03: Admin-Gated Write Path for Eligibility Controls Summary

**Two SECURITY DEFINER RPCs (`set_reference_override`, `set_org_learning_switches`) close the two live write-path gaps (organizations has no org-admin write policy; proposals_update has no role check) that would otherwise let any org member flip the confidentiality controls Plan 02's read-path RPC relies on.**

## Accomplishments
- Authored `set_reference_override(p_proposal_id uuid, p_value boolean)` — admin-gated (RAISE 'not authorized' if caller role not in admin/super_admin), org-scoped UPDATE, tri-state-safe (NULL passthrough)
- Authored `set_org_learning_switches(p_learn_from_won, p_learn_from_submitted, p_learn_from_lost)` — admin-gated, org-scoped, updates only the 3 `learn_from_*` columns (column-scoped by construction, no other `organizations` columns touched)
- Both RPCs REVOKE'd from PUBLIC/anon and GRANT'd only to authenticated/service_role
- Authored `verify-write-gating.sql` with positive (admin-allow), negative (non-admin-deny, both RPCs), and cross-org (0-row-effect) checks, each wrapped `BEGIN...ROLLBACK`, plus a manual UAT fallback for Plan 07 if the `request.jwt.claims` GUC simulation isn't honored by the MCP `execute_sql` connection
