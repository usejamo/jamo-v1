<objective>
Fix the root cause of the regulatory-grounding correctness bug on the CLIENT side: the two-tier
collapse in `fetchRagChunks`. Replace the merged `ragChunks` payload field with a split that carries
`regulatoryChunks`, `proposalChunks`, and `regulatoryCount` separately all the way to the edge
function. This is the contract half of the (b) change — the edge half is Plan 02, which ships/deploys
together with this.

Purpose: Keep tier identity and retrieval meta alive so the edge can condition on `regulatoryCount`
specifically (never a merged length). Both observed symptoms (mislabeling proposal chunks as
regulatory; silently swallowing zero-regulatory-retrieval) are downstream of this collapse.
Output: Updated payload type + hook that threads the split through every call site.
</objective>

<decision>
Payload shape (planner's call, per BRIEF): use the EXPLICIT THREE-FIELD split, NOT the
systemPromptBlock reuse. Replace `ragChunks` on `GenerateSectionPayloadV2` with:
  regulatoryChunks: RagChunk[]
  proposalChunks:   RagChunk[]
  regulatoryCount:  number
where `RagChunk = { content: string; source: string; agency?: string; doc_type?: string }`.
Rationale: the edge (Plan 02) must build the CRO system prompt and gate the compliance clause on
`regulatoryCount` itself; the raw tiers + count give it exactly that. The retrieve-context labeling
CODE pattern is copied into the edge (Plan 02), but the raw tiers are threaded, not the prebuilt block.
</decision>
