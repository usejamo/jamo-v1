<domain>
## Phase Boundary

Three deliverables in **strict priority order** so the correctness fix ships even if the seeder slips.
Priority is load-bearing: **(b) before (a) before the seeder.**

1. **(b) PRIMARY — Regulatory grounding correctness (live bug).** Retrieval mislabels proposal-history
   chunks as regulatory context and silently swallows zero-regulatory-retrieval; the section-generation
   prompt asserts ICH-GCP compliance unconditionally. Fix the root cause (a two-tier collapse in
   `fetchRagChunks`), keep tiers separate end-to-end, and make the compliance claim conditional on
   actually having regulatory grounding (`regulatoryCount > 0`).
2. **(a) SIBLING — Ingest supersession hardening.** `ingest_regulatory_document` silently no-ops when
   `--supersedes` is passed but unresolved; make it RAISE (only when a supersedes key is passed AND not
   found — never on plain non-superseding ingests).
3. **(third) — Starter-corpus seeder.** One-command, manifest-driven seeder (Approach A: manifest +
   folder convention) to populate the currently empty regulatory corpus. Depends on (a) and (b) being
   correct.

If the phase is time-pressured: (b) ships first, then (a), then the seeder.
</domain>

## Implementation Decisions (LOCKED — from BRIEF)

### (b) Tier separation (root-cause fix — do NOT patch the two symptoms independently)
- Stop merging in `fetchRagChunks` (`src/hooks/useProposalGeneration.ts`, ~lines 214–216). Carry
  `regulatoryChunks` and `proposalChunks` (and at least `regulatoryCount`) **separately** all the way
  through to `generate-proposal-section`. Reusing `retrieve-context`'s already-correct
  `systemPromptBlock` end-to-end is a viable alternative to rebuilding — **planning's call.**
- Replace the single `ragChunks` field on `GenerateSectionPayloadV2`; thread the split through both call
  sites (`generateAll` ~475, `generateSection` ~543) and `streamSection`.
- Edge (`generate-proposal-section/index.ts`): label regulatory chunks under `[REGULATORY CONTEXT]`,
  proposal-history under a separate `[PROPOSAL HISTORY]` header (never conflate, ~lines 140–142 &
  252–254). When `regulatoryCount === 0`, emit an explicit "no regulatory grounding available for this
  section/geography" marker.
- **Conditional compliance assertion (the part that matters most):** `CRO_PROPOSAL_SYSTEM_PROMPT`
  (~line 27) asserts "compliant with ICH-GCP (E6 R2/R3)" **unconditionally**. Make that assertion
  **conditional on `regulatoryCount > 0`.** With no grounding, the prompt must NOT assert compliance for
  that section — fall back to existing CRITICAL RULES (`[PLACEHOLDER]`, never fabricate). A not-found
  marker alongside an unconditional compliance claim is contradictory and the assertion wins.

### (a) Ingest supersession raise
- New migration `CREATE OR REPLACE` on `ingest_regulatory_document`
  (`supabase/migrations/20260708000005_ingest_regulatory_rpc.sql` is the current def). Applied via
  **Supabase MCP `apply_migration`** — NOT `db push` (diverged history).
- **Raise condition (state precisely):** raise iff `p_supersedes_document_key IS NOT NULL` AND the
  active-document lookup found nothing. When the key IS NULL, skip the branch entirely and ingest
  normally — **do NOT** implement as "raise whenever `v_supersedes_id IS NULL`" (that would break every
  GLOBAL starter doc). DB-only change — no edge deploy.

### (third) Seeder (Approach A: manifest + folder convention)
- **Manifest** `scripts/regulatory-starter-manifest.ts` — typed entries
  `{ documentKey, title, agency, geography: string[], phase?, therapeuticArea?, effectiveDate?, status?, supersedes?, folder? }`;
  `folder` defaults to `documentKey`. Inline COMMENTS carry rationale (esp. E6 non-GLOBAL note).
- **Folders** `regulatory-docs/<documentKey>/*.pdf` — operator-curated, PDFs `.gitignore`d, folder
  structure documented. Each folder's PDFs = one logical doc.
- **Command** `npm run seed:regulatory` → `scripts/seed-regulatory.ts`, **reusing the ported ingest
  path** (`embedBatch` + `chunkDocument` + `ingest_regulatory_document` RPC — do not re-implement
  embedding).
- **Structural req #1 — supersession ordering independent of manifest order:** topologically sort by
  `supersedes` links (or validate every target appears earlier); hard-fail on missing/cyclic.
- **Structural req #2 — batch pre-validation before ANY write/embedding call:** confirm every folder
  exists with ≥1 PDF, every `supersedes` target present, no duplicate `documentKey`s, acyclic graph.
  Aggregate all failures into one report, exit non-zero **without spending an embedding call**.
  All-or-nothing at batch level. Provide `--validate-only` mode.
- **Geography / E6 (locked — launching without Japan):** starter set is **R3-only**, no R2, no
  `--supersedes` on the E6 pair. `ICH-E6R3` geography = `{US,EU,UK}` **NOT GLOBAL** (deliberate — keeps
  E6 from citing R3 for a Japan query; a manifest COMMENT MUST state this). Everything else (E8, E9, E3,
  M3…) → `GLOBAL` canon (`org_id` NULL). Documented consequence: Japan proposal gets no ICH E6 — the
  legitimate zero-retrieval that (b) makes visible.
- **Default manifest contents are a PROPOSAL** pending clinical-domain review — draft it, do NOT treat
  the drafted list as a locked spec.

### Deploy discipline (from 14.5, carried forward)
- Migrations via Supabase MCP `apply_migration` (NOT `db push`).
- Edge deploy explicit: `npx supabase functions deploy generate-proposal-section --project-ref fuuvdcvbliijffogjnwg`.
  **generate-proposal-section is new-to-14.6 and MUST be redeployed** (not touched in 14.5).
  `retrieve-context` is UNCHANGED (already returns the split).
- Client↔edge contract change: `useProposalGeneration.ts` + `generate-proposal-section` ship together.
- **Pause before every live step:** live DB apply, edge deploy, and any credit-spending live run.

### Claude's Discretion

- Prompt-assembly refactor structure in the edge function.
- Topo-sort vs earlier-in-order validation for the seeder.
- Test file organization (unit test the prompt-assembly branch on `regulatoryCount`).

## Specific Ideas / Verification (from BRIEF)

1. **(b) tier separation** — a section with `regulatoryCount=0` + proposal chunks present does NOT emit
   proposal chunks under `[REGULATORY CONTEXT]`; prompt contains the "no regulatory grounding" marker and
   does NOT assert ICH-GCP compliance. A section with `regulatoryCount>0` retains the assertion + a
   populated `[REGULATORY CONTEXT]`. (Unit-test the prompt-assembly branch on `regulatoryCount`;
   live-smoke a Japan-scoped section after seeding.)
2. **(b) deploy** — `generate-proposal-section` redeployed; client + edge payload contract match.
3. **(a) raise** — `ingest_regulatory_document` with a non-existent/inactive supersedes key RAISES;
   with `p_supersedes_document_key = NULL` succeeds normally (GLOBAL-doc regression guard).
4. **(third) pre-validation** — seeder against a manifest with missing folder / missing supersedes
   target / duplicate key fails BEFORE any embedding call, aggregated message.
5. **(third) end-to-end** — `npm run seed:regulatory` populates corpus in dependency order; a US Phase-2
   oncology "Study Design" section retrieves seeded E6(R3); a JP-scoped section legitimately retrieves
   none and surfaces the (b) marker.
</specifics>
