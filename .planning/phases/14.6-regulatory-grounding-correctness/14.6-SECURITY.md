## Accepted Risks Log

The following threats are formally accepted (disposition = `accept`), not mitigated in code.
This is their first recorded entry — no prior SECURITY.md existed for this phase.

- **T-14.6-01** — Client→edge chunk payload (`regulatoryChunks`/`proposalChunks`/`regulatoryCount`
  split across three fields instead of one). Accepted because chunks are always sourced from
  `retrieve-context` (org-scoped RLS) — the split does not introduce a new trust boundary. The
  residual prompt-injection surface from untrusted chunk *content* is separately mitigated under
  T-14.6-02 (`sanitizeChunkText`), and the residual spoofing surface from a desynced client count
  is separately mitigated under T-14.6-03 (`groundedCount` derivation). Accepted by: phase 14.6
  threat model author. Revisit if `retrieve-context`'s RLS scoping ever changes.

- **T-14.6-05** — Injection (SQLi) via `ingest_regulatory_document` RPC arguments. Accepted because
  all arguments are plpgsql typed parameters bound by value (no dynamic SQL / `EXECUTE` / `format()`
  in the function body); the only `RAISE` uses a `%` placeholder, not string concatenation. This is
  standard parameterized-procedure behavior, not a residual risk requiring code changes. Accepted
  by: phase 14.6 threat model author.
