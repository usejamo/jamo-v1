### `supabase/migrations/NNNN_regulatory_documents.sql` (migration/model, CRUD + state-machine)

**Analog:** `supabase/migrations/20260320000015_chunks_table.sql`

**Table + index + RLS shape to copy** (full file, 44 lines):
```sql
CREATE TABLE chunks (
  id                UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  org_id            UUID NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
  doc_type          TEXT NOT NULL CHECK (doc_type IN ('regulatory', 'proposal')),
  ...
);
CREATE INDEX idx_chunks_org_doctype ON chunks(org_id, doc_type);
ALTER TABLE chunks ENABLE ROW LEVEL SECURITY;
CREATE POLICY chunks_org_isolation ON chunks
  USING (org_id = (SELECT org_id FROM user_profiles WHERE id = auth.uid()));
```
Copy: `CREATE TABLE` shape, `default gen_random_uuid()` PK convention, `TIMESTAMPTZ NOT NULL DEFAULT NOW()` for `created_at`, `ENABLE ROW LEVEL SECURITY` immediately after table creation.

**DO NOT COPY:** the RLS policy body `USING (org_id = (SELECT org_id FROM user_profiles WHERE id = auth.uid()))` — `user_profiles.id` is NOT the auth user id (own generated PK); the FK to `auth.users` is `user_profiles.user_id`. This policy is a pre-existing likely-broken landmine. For the new regulatory-read policy, use `private.get_user_org_id()` (see RLS section below) or no user_profiles join at all if the policy doesn't need org scoping.

**Immutability trigger — no existing analog.** Write as a small standalone `plpgsql` trigger function:
```sql
CREATE OR REPLACE FUNCTION private.enforce_regulatory_document_key_immutable()
RETURNS trigger
LANGUAGE plpgsql
AS $$
BEGIN
  IF NEW.document_key <> OLD.document_key THEN
    RAISE EXCEPTION 'document_key is immutable (attempted % -> %)', OLD.document_key, NEW.document_key;
  END IF;
  RETURN NEW;
END;
$$;

CREATE TRIGGER regulatory_documents_document_key_immutable
  BEFORE UPDATE ON regulatory_documents
  FOR EACH ROW EXECUTE FUNCTION private.enforce_regulatory_document_key_immutable();
```
Follow the repo's existing trigger-creation convention from the same migration file style (`CREATE TRIGGER ... BEFORE INSERT OR UPDATE ON chunks FOR EACH ROW EXECUTE FUNCTION tsvector_update_trigger(...)` at `20260320000015_chunks_table.sql:23-26`) — same `CREATE TRIGGER ... BEFORE ... FOR EACH ROW EXECUTE FUNCTION` shape, just a custom plpgsql function body instead of a built-in trigger function.

```sql
CREATE OR REPLACE FUNCTION match_chunks_vector(
  query_embedding    extensions.vector(1536),
  org_id_filter      UUID,
  agencies_filter    TEXT[],
  therapeutic_areas_filter TEXT[],
  similarity_threshold FLOAT,
  match_count        INT
)
RETURNS TABLE (
  id UUID, content TEXT, source TEXT, agency TEXT,
  therapeutic_area TEXT, doc_type TEXT, vector_score FLOAT
)
LANGUAGE sql
SECURITY DEFINER
SET search_path = public, extensions
AS $$
  SELECT id, content, source, agency, therapeutic_area, doc_type,
    1 - (embedding <=> query_embedding) AS vector_score
  FROM chunks
  WHERE org_id = org_id_filter
    AND doc_type = 'regulatory'
    AND (agencies_filter IS NULL OR agency = ANY(agencies_filter))
    AND (therapeutic_areas_filter IS NULL OR therapeutic_area = ANY(therapeutic_areas_filter))

  LIMIT match_count;
$$;
```

### `supabase/migrations/NNNN_ingest_regulatory_rpc.sql` (new SECURITY DEFINER RPC, transactional batch)

**Analog:** `supabase/migrations/20260528120000_append_resolved_item_rpc.sql` (full 80 lines read) — **this is the strongest analog in the repo** for "one plpgsql function doing multiple dependent writes atomically, with branching upsert-or-update logic and explicit grant/revoke."

**Copy this shape exactly:**
```sql
create or replace function public.append_resolved_item(
  p_proposal_id uuid, p_user_id uuid, p_org_id uuid, p_entry jsonb
) returns jsonb
language plpgsql
security invoker          -- NOTE: use `security definer` instead for the ingest RPC (this file is
                          -- the repo's one deliberate SECURITY INVOKER divergence — read its own
                          -- comment: "DELIBERATE DIVERGENCE... first SECURITY INVOKER RPC in this
                          -- codebase". The ingest RPC needs SECURITY DEFINER like every other RPC
                          -- in the repo, since it must write regulatory rows with org_id NULL,
                          -- which the calling service-role session may not otherwise have rights to.)
set search_path = public
as $$
declare
  v_existing jsonb;
  ...
begin
  -- Step 1: lock / look up existing row
  select ... into v_existing from chat_sessions where ... for update;
  if not found then
    insert into chat_sessions (...) values (...) on conflict (...) do nothing;
    -- re-fetch under lock to handle concurrent-insert race
  end if;
  -- Step 2..4: combine, transform, write back
  update chat_sessions set ... where ...;
  return v_capped;
end;
$$;

revoke all on function public.append_resolved_item(uuid, uuid, uuid, jsonb) from public;
grant execute on function public.append_resolved_item(uuid, uuid, uuid, jsonb) to authenticated;
```

**Apply this exact structure to the ingest RPC:**
1. `SELECT id FROM regulatory_documents WHERE document_key = $1` (branch point, mirrors the `select ... for update; if not found` pattern)
2. No match → `INSERT INTO regulatory_documents (...)`. Match → `UPDATE regulatory_documents SET title=..., agency=..., ... WHERE id = $found_id` — **never include `document_key` in the SET list** (per Pitfall 3 in RESEARCH.md — this mirrors how `append_resolved_item` never rewrites the row's identity columns either).
3. `DELETE FROM chunks WHERE regulatory_document_id = $parent_id` (scoped exactly like the analog's `WHERE proposal_id = $1 AND user_id = $2`, i.e. always scoped to the specific parent, never broader).
4. `INSERT INTO chunks (...)` reinsert (bulk, from a `jsonb` array param of pre-embedded chunk rows, since embeddings must be computed client-side by the tsx CLI before calling the RPC — Postgres has no OpenAI access).
5. If `p_supersedes_document_key` is provided: `UPDATE regulatory_documents SET status='superseded', superseded_by=$new_id WHERE document_key = $2 AND status='active'`, then set the new row's `supersedes` to that resolved id.
6. Wrap steps 1-5 in the implicit single-statement-function transaction (the whole plpgsql function body is one transaction already — no explicit `BEGIN/COMMIT` needed, exactly like the analog).
7. `SECURITY DEFINER` + `SET search_path = public, extensions` (need `extensions` for the `vector` type in chunk inserts) + `REVOKE ALL ... FROM PUBLIC` + `GRANT EXECUTE ... TO service_role` (not `authenticated` — this RPC is called only by the tsx ingest CLI running as service-role, unlike `append_resolved_item` which grants to `authenticated`). Use the `private.vault_store_sf_tokens` grant pattern instead for the exact `service_role`-only grant shape:
```sql
-- Source: supabase/migrations/20260506000026_salesforce_integration.sql:83-84
REVOKE ALL ON FUNCTION private.vault_store_sf_tokens FROM PUBLIC;
GRANT EXECUTE ON FUNCTION private.vault_store_sf_tokens TO service_role;
```

```ts
function loadEnv(): Record<string, string> {
  const out: Record<string, string> = { ...process.env } as Record<string, string>
  try {
    const raw = readFileSync(resolve(process.cwd(), '.env'), 'utf8')
    for (const line of raw.split('\n')) {
      const m = line.match(/^\s*([A-Z0-9_]+)\s*=\s*(.*)\s*$/)
      if (!m) continue
      const key = m[1]
      let val = m[2].trim()
      if ((val.startsWith('"') && val.endsWith('"')) || (val.startsWith("'") && val.endsWith("'"))) {
        val = val.slice(1, -1)
      }
      if (out[key] === undefined || out[key] === '') out[key] = val
    }
  } catch { /* .env optional */ }
  return out
}
```
