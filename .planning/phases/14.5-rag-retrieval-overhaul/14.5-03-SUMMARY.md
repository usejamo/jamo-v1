## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Security correctness] Ingest RPC EXECUTE grant leaked to anon/authenticated**
- **Found during:** Task 2 (assertion 5)
- **Issue:** Supabase default privileges GRANT EXECUTE to anon/authenticated/service_role directly at function creation. `REVOKE ALL ... FROM PUBLIC` (from Plan 02) did not remove those direct grants, so `authenticated` retained EXECUTE on the SECURITY DEFINER ingest RPC — a privilege-escalation surface (T-14.5-05).
- **Fix:** Added `REVOKE ALL ... FROM PUBLIC, anon, authenticated` to migration 005 and applied a corrective live migration. Re-verified: svc=true, auth=false, anon=false.
- **Files modified:** supabase/migrations/20260708000005_ingest_regulatory_rpc.sql
- **Verification:** has_function_privilege re-check confirms only service_role.
- **Committed in:** `fix(14.5-03): harden ingest RPC grant`

### Plan test-authoring discrepancy (not a code change)

**2. [Rule 4-adjacent - flagged, not silently changed] Assertion 2b expectation contradicts BRIEF**
- The plan's assertion 2b expected a chunk row with BOTH org_id and regulatory_document_id set to violate `chunks_tier_pairing`. The BRIEF explicitly leaves regulatory `org_id` unconstrained ("so a future per-org regulatory tier is possible"), so the CHECK — `(org NOT NULL AND reg_doc NULL) OR (reg_doc NOT NULL)` — intentionally PERMITS both-set. Verified analytically: neither_set=false (rejected), proposal_tier=true, regulatory_tier=true, both_set=true.
- **Resolution:** The constraint is correct per BRIEF; the plan's smoke expectation was mis-authored. No code/constraint change. Only the neither-set case (the real invalid state) is rejected, and that was verified live.
