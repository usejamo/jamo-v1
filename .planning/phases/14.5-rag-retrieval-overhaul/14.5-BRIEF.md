# Phase 14.5 — RAG Retrieval Overhaul + Regulatory Corpus Foundation

> Authoritative brief. Supersedes any conflicting summary. Consumed by `/gsd-plan-phase 14.5`.
> Source: user brief (in-conversation) + 3 finalized edits (document_key) + confirmed immutability guardrails.

## Objective

Make proposal generation retrieve relevant, version-current regulatory content by fixing query
construction, introducing a global regulatory tier, and adding a versioned `regulatory_documents`
parent table. The regulatory corpus is currently empty (all 171 chunks are `doc_type='proposal'`,
tag columns 100% NULL); **this phase builds the structure and wiring, not the corpus content itself.**

## Current-state facts (verified 2026-07-08, against live DB + deployed code)

- `chunks`: 171 rows, all `doc_type='proposal'`, org `…0001`; `agency`/`guideline_type`/`therapeutic_area` 100% NULL; metadata keys populated = `document_id`, `tokenCount`, `sectionRef`. `org_id` currently NOT NULL; RLS enabled (`chunks_org_isolation`).
- Retrieval RPCs are `SECURITY DEFINER`; `retrieve-context` runs as service-role; tenant isolation is the explicit `WHERE org_id = org_id_filter`, not RLS.
- Hybrid = two RPCs per doc_type (HNSW cosine vector + Postgres `ts_rank` FTS), merged in TS as `0.7·vector + 0.3·text`. Not one SQL query; not BM25.
- `fetchRagChunks` query text = the bare section name only (`query = sectionName`); per-section (one call per section).
- Structured proposal attributes exist as `proposals` columns: `indication`, `therapeutic_area`, `study_phase`, `study_type`, `client_name`, `services_requested`, `due_date`. **No `geography`/`countries` column, no `modality` column.** None of these feed retrieval today.
- No versioning/supersession/effective-date/recency anywhere in the RAG path.

## SCHEMA

**Create table `regulatory_documents`:**
- `id` uuid PK default gen_random_uuid
- `document_key` text **NOT NULL UNIQUE** — the stable, operator-supplied logical-document identifier; the resolution target for supersession and re-ingest. **Distinct from `source`** (do NOT overload source as the key).
- `title` text NOT NULL
- `agency` text NOT NULL
- `therapeutic_area` text NULL
- `phase` text[] NULL (NULL = applies to all phases)
- `geography` text[] NOT NULL (values like `{'US'}`, `{'EU'}`, `{'JP'}`, `{'GLOBAL'}`)
- `effective_date` date NULL
- `status` text NOT NULL default `'active'` CHECK (status IN ('active','superseded','withdrawn'))
- `supersedes` uuid NULL FK regulatory_documents(id)
- `superseded_by` uuid NULL FK regulatory_documents(id)
- `source` text NOT NULL — free-text provenance (filename/URL); continues to feed chunk-level citations. NOT the identity key.
- `created_at` timestamptz default now; `updated_at` timestamptz

**Immutability guardrail (confirmed design):** add a `BEFORE UPDATE` trigger on `regulatory_documents`
that raises if `NEW.document_key <> OLD.document_key`. Combined with parent update-in-place (below),
this guarantees `document_key` and `id` never drift, so `supersedes`/`superseded_by` and
`chunks.regulatory_document_id` FK targets can never dangle.

**Alter `chunks`:**
- add `regulatory_document_id` uuid NULL FK regulatory_documents(id) ON DELETE CASCADE
- drop NOT NULL on `org_id`
- add CHECK enforcing tier pairing: a proposal chunk has `org_id` NOT NULL AND `regulatory_document_id` NULL; a regulatory chunk has `regulatory_document_id` NOT NULL (leave regulatory `org_id` unconstrained so a future per-org regulatory tier is possible, but this phase writes regulatory chunks with `org_id` NULL only).
- Do NOT duplicate agency/therapeutic_area/geography onto regulatory chunks; those live on the parent and are read via join at retrieval.

**Alter `proposals`:**
- add `geography` text[] NULL
- Wire a geography field in the wizard (`Step1StudyInfo.tsx`) that persists to this column.
- Back the existing (currently empty, unbacked) `studyInfo.countries` payload field from `proposals.geography` so it carries real values into generation.
- Do NOT add a modality column.

## INGEST CLI (`scripts/ingest-regulatory.ts`)

Add flags: `--document-key` (**required**), `--geography` (comma list, required), `--effective-date`
(optional), `--status` (optional, default active), `--phase` (optional comma list), `--supersedes`
(optional, a predecessor's **document_key**). Keep `--agency` and `--therapeutic-area`.

Per run:
- Upsert one `regulatory_documents` row. **Replace-in-place keys on `document_key`**: re-ingest →
  `WHERE document_key = $1` → **UPDATE the parent row in place by its `id`** (never DELETE+INSERT the
  parent; `document_key` is never in the SET clause) + delete-then-reinsert its chunks.
- Write each chunk with `org_id` NULL, `doc_type` `'regulatory'`, `regulatory_document_id` = that
  parent id, and `guideline_type` kept per-chunk from `sectionRef`. (chunk `source` stays the
  filename for citations.)
- The CASCADE-triggering delete on re-ingest is scoped to `chunks WHERE regulatory_document_id = <id>`
  only — never the parent.

`--supersedes`: resolve via `WHERE document_key = $1 AND status='active'`. On match: set that
document's `status='superseded'` and `superseded_by` = new id; set the new document's `supersedes`
= old id.

## RETRIEVAL RPCs

**Regulatory RPCs (`match_chunks_vector`, `match_chunks_fts`):** join `regulatory_documents` on
`chunks.regulatory_document_id`. Change the tenant clause to `(org_id = org_id_filter OR org_id IS NULL)`.
Always apply `rd.status = 'active'`. Accept nullable filter params `therapeutic_areas_filter`,
`phases_filter` (new), `geographies_filter` (new), applied as pre-filter WHERE clauses against the
parent columns; geography matches when `rd.geography && geographies_filter OR rd.geography && '{GLOBAL}'`.
Keep the HNSW cosine vector path and the ts_rank FTS path.

**Proposal RPCs (`match_chunks_vector_proposals`, `match_chunks_fts_proposals`):** leave the
`org_id = org_id_filter` isolation exactly as is; add no metadata filters.

## QUERY CONSTRUCTION (`fetchRagChunks`)

Replace the bare-section-title query. Build the query string **deterministically (no LLM)** from the
section name plus the proposal's structured attributes, e.g.
`"{sectionName} — {study_phase} {therapeutic_area} study of {indication}"`, omitting any attribute
that is null and keeping the string clean. Embed that composed string. Pass the proposal's
`therapeutic_area`, `study_phase`, and `geography` into the regulatory retrieval call as the filter
params above.

## GRADED FILTER RELAXATION (`retrieve-context`, app layer not SQL)

Call the regulatory RPCs first with the full tight filter set. If the returned count is below the
regulatory budget, re-call relaxing one dimension at a time in this order: drop `phases_filter`,
then drop `therapeutic_areas_filter`. Always keep status `'active'` and the geography filter. Record
which relaxation level produced the results.

## RETRIEVAL ASSEMBLY (`retrieve-context`)

Apply a per-doc_type budget: retrieve top-N regulatory and top-M proposal chunks independently and
return both, rather than merging into one global top-k where one type can crowd out the other. Keep
the existing 70/30 vector/FTS weighting within each doc_type.

## RLS

Add a `chunks` SELECT policy permitting rows where `doc_type='regulatory' AND org_id IS NULL` for any
authenticated user, alongside the existing `chunks_org_isolation` policy. (Defense-in-depth; the
SECURITY DEFINER retrieval path is unaffected.)

## OUT OF SCOPE — DO NOT IMPLEMENT THIS PHASE

Modality column or filter; recency or time-decay ranking; generic `metadata->>` jsonb filtering; LLM
or HyDE query synthesis; a per-org regulatory corpus ingest path (schema must permit it, but build
nothing for it); any change to proposal-side filtering beyond existing org isolation.
