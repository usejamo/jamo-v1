<domain>
## Phase Boundary

Make proposal generation retrieve relevant, version-current regulatory content by fixing query
construction, introducing a global (`org_id` NULL) regulatory tier, and adding a versioned
`regulatory_documents` parent table with supersession.

**This phase builds STRUCTURE and WIRING, not corpus content.** The regulatory corpus is currently
empty (all 171 chunks are `doc_type='proposal'`, tag columns 100% NULL). Retrieval is driven today by
bare section-title queries with no proposal-attribute signal and no proposal/regulatory scoping.

Delivered: versioned parent table + document_key-keyed supersession; global regulatory chunk tier;
chunks tier-pairing CHECK + `regulatory_document_id` FK; `proposals.geography` + wizard wiring +
`studyInfo.countries` backing; ingest-CLI flags; deterministic attribute-based query construction;
graded filter relaxation; per-`doc_type` retrieval budgets; regulatory-read RLS defense-in-depth.

</domain>

### Post-Research Decisions (LOCKED 2026-07-08 — user-confirmed after research)

These three resolve gaps the BRIEF assumed away. Items 2 and 3 **expand phase scope** beyond the
original BRIEF (a blob migration and an ingest RPC). Both are mandatory, not optional. Where these
conflict with a literal BRIEF statement, **these win**.

1. **Ingest CLI runtime → port to tsx/Node.** Rewrite `scripts/ingest-regulatory.ts` to run under
   tsx/Node following the proven `scripts/backfill-proposal-chunks.ts` pattern (raw `fetch` to
   OpenAI; no Deno). **Do NOT install Deno.** Converges on one runtime, makes the E2E verification
   (R2→R3 supersession) runnable in the dev env, and lets tests be Vitest-native.

2. **`proposals.geography` → real column, migrate the blob, retire the blob.** Add
   `proposals.geography text[]`. One-time data migration: parse `regions` out of the
   `{services, regions}` JSON currently stuffed in `proposals.description` into the new column.
   Point the wizard at the real column; **stop writing `regions` into `description`**.
   - **VERIFY FIRST (blocking sub-task):** audit whether anything READS `description`'s JSON at
     generation or display time (`ProposalDetail.tsx` `buildProposalInput()` is the known parser —
     confirm all readers). If a reader exists, repoint it to the real column(s) **in the same change**
     — otherwise this ships a silent empty-`regions` regression.
   - **Also verify `services`:** confirm whether `proposals.services_requested` is the real read
     path for services. **If yes → retire the entire `description` JSON blob in this migration**
     (stop writing services too). **If no →** do item 2 as written and leave a services-only blob,
     explicitly noted as pending a future cleanup. This makes "keep services" a verified decision,
     not an assumption.

3. **Ingest atomicity → single SECURITY DEFINER Postgres RPC.** Move the whole re-ingest sequence
   (parent upsert → supersession flip → chunk delete → chunk reinsert) into ONE `SECURITY DEFINER`
   Postgres function so it runs in a single implicit transaction. The ported Node CLI calls that RPC
   once. Any step fails → whole thing rolls back → R2 stays `active`. **Do NOT** hand-roll
   compensation logic across discrete supabase-js calls. Rationale: the one operation that can fail
   is the one whose partial state is a silent, unmonitored gap in the regulatory canon the product
   depends on — consequence, not frequency, governs here.

### Current-state facts (verified 2026-07-08 against live DB + deployed code)
- `chunks`: 171 rows, all `doc_type='proposal'`, org `…0001`; `agency`/`guideline_type`/`therapeutic_area` 100% NULL; metadata keys populated = `document_id`, `tokenCount`, `sectionRef`. `org_id` currently NOT NULL; RLS enabled (`chunks_org_isolation`).
- Retrieval RPCs are `SECURITY DEFINER`; `retrieve-context` runs as service-role; tenant isolation is the explicit `WHERE org_id = org_id_filter`, not RLS.
- Hybrid = two RPCs per doc_type (HNSW cosine vector + Postgres `ts_rank` FTS), merged in TS as `0.7·vector + 0.3·text`. Not one SQL query; not BM25.
- `fetchRagChunks` query text = bare section name only (`query = sectionName`); per-section (one call per section).
- Structured proposal attributes are `proposals` columns: `indication`, `therapeutic_area`, `study_phase`, `study_type`, `client_name`, `services_requested`, `due_date`. No `geography`/`countries`, no `modality`. None feed retrieval today.
- No versioning/supersession/effective-date/recency anywhere in the RAG path.

### Schema — create `regulatory_documents`
- `id` uuid PK default gen_random_uuid
- `document_key` text **NOT NULL UNIQUE** — stable operator-supplied logical-document identifier; resolution target for supersession and re-ingest. **Distinct from `source`** (do NOT overload source as the key).
- `title` text NOT NULL
- `agency` text NOT NULL
- `therapeutic_area` text NULL
- `phase` text[] NULL (NULL = applies to all phases)
- `geography` text[] NOT NULL (values like `{'US'}`, `{'EU'}`, `{'JP'}`, `{'GLOBAL'}`)
- `effective_date` date NULL
- `status` text NOT NULL default `'active'` CHECK (status IN ('active','superseded','withdrawn'))
- `supersedes` uuid NULL FK regulatory_documents(id)
- `superseded_by` uuid NULL FK regulatory_documents(id)
- `source` text NOT NULL — free-text provenance (filename/URL); feeds chunk-level citations. NOT the identity key.
- `created_at` timestamptz default now; `updated_at` timestamptz

### Schema — immutability guardrail (LOCKED)
- Add a `BEFORE UPDATE` trigger on `regulatory_documents` that raises if `NEW.document_key <> OLD.document_key`.
- Combined with parent update-in-place, guarantees `document_key` and `id` never drift, so `supersedes`/`superseded_by` and `chunks.regulatory_document_id` FK targets can never dangle.

### Schema — alter `chunks`
- Add `regulatory_document_id` uuid NULL FK regulatory_documents(id) ON DELETE CASCADE.
- Drop NOT NULL on `org_id`.
- Add CHECK enforcing tier pairing: proposal chunk has `org_id` NOT NULL AND `regulatory_document_id` NULL; regulatory chunk has `regulatory_document_id` NOT NULL (leave regulatory `org_id` unconstrained for a future per-org tier, but this phase writes regulatory chunks with `org_id` NULL only).
- Do NOT duplicate agency/therapeutic_area/geography onto regulatory chunks; those live on the parent, read via join at retrieval.

### Schema — alter `proposals`
- Add `geography` text[] NULL.
- Wire a geography field in the wizard (`Step1StudyInfo.tsx`) that persists to this column.
- Back the existing (currently empty, unbacked) `studyInfo.countries` payload field from `proposals.geography` so it carries real values into generation.
- Do NOT add a modality column.

### Ingest CLI (`scripts/ingest-regulatory.ts`)
- Add flags: `--document-key` (**required**), `--geography` (comma list, required), `--effective-date` (optional), `--status` (optional, default active), `--phase` (optional comma list), `--supersedes` (optional, a predecessor's **document_key**). Keep `--agency` and `--therapeutic-area`.
- Per run: upsert one `regulatory_documents` row. Replace-in-place keys on `document_key`: re-ingest → `WHERE document_key = $1` → **UPDATE the parent row in place by its `id`** (never DELETE+INSERT the parent; `document_key` never in the SET clause) + delete-then-reinsert its chunks.
- Write each chunk with `org_id` NULL, `doc_type` `'regulatory'`, `regulatory_document_id` = that parent id, `guideline_type` kept per-chunk from `sectionRef`. Chunk `source` stays the filename for citations.
- CASCADE-triggering delete on re-ingest scoped to `chunks WHERE regulatory_document_id = <id>` only — never the parent.
- `--supersedes`: resolve via `WHERE document_key = $1 AND status='active'`. On match: set that document's `status='superseded'` and `superseded_by` = new id; set new document's `supersedes` = old id.

### Retrieval RPCs
- **Regulatory RPCs (`match_chunks_vector`, `match_chunks_fts`):** join `regulatory_documents` on `chunks.regulatory_document_id`. Change tenant clause to `(org_id = org_id_filter OR org_id IS NULL)`. Always apply `rd.status = 'active'`. Accept nullable filter params `therapeutic_areas_filter`, `phases_filter` (new), `geographies_filter` (new), applied as pre-filter WHERE clauses against parent columns; geography matches when `rd.geography && geographies_filter OR rd.geography && '{GLOBAL}'`. Keep HNSW cosine vector path and ts_rank FTS path.
- **Proposal RPCs (`match_chunks_vector_proposals`, `match_chunks_fts_proposals`):** leave `org_id = org_id_filter` isolation exactly as is; add no metadata filters.

### Query construction (`fetchRagChunks`)
- Replace bare-section-title query. Build the query string **deterministically (no LLM)** from section name plus proposal structured attributes, e.g. `"{sectionName} — {study_phase} {therapeutic_area} study of {indication}"`, omitting any null attribute and keeping the string clean. Embed that composed string. Pass proposal's `therapeutic_area`, `study_phase`, and `geography` into the regulatory retrieval call as the filter params.

### Graded filter relaxation (`retrieve-context`, app layer not SQL)
- Call regulatory RPCs first with full tight filter set. If returned count is below the regulatory budget, re-call relaxing one dimension at a time in this order: drop `phases_filter`, then drop `therapeutic_areas_filter`. Always keep status `'active'` and the geography filter. Record which relaxation level produced results.

### Retrieval assembly (`retrieve-context`)
- Apply per-doc_type budget: retrieve top-N regulatory and top-M proposal chunks independently and return both, rather than merging into one global top-k where one type crowds out the other. Keep existing 70/30 vector/FTS weighting within each doc_type.

### RLS
- Add a `chunks` SELECT policy permitting rows where `doc_type='regulatory' AND org_id IS NULL` for any authenticated user, alongside existing `chunks_org_isolation`. Defense-in-depth; the SECURITY DEFINER retrieval path is unaffected.

### Deployment constraints (LOCKED — repo-specific)
- Migrations via Supabase MCP `apply_migration` — **NOT `supabase db push`** (migration history diverged here).
- Edge functions deploy via CLI (`npx supabase functions deploy <slug> --project-ref fuuvdcvbliijffogjnwg`) and MUST be deployed explicitly — committed ≠ live in this repo.

## Specific Ideas

### Verification protocol (from BRIEF)
Ingest E6(R2) and E6(R3) with **distinct `--document-key` values** (`ICH-E6R2`, `ICH-E6R3`), agency ICH, geography `{'US','EU','GLOBAL'}`.
1. Ingest R2 first (active). Confirm a Phase 2 oncology US proposal's "Study Design" section retrieves it.
2. Then ingest R3 with `--supersedes=ICH-E6R2`.
3. Confirm R2 flips to `status='superseded'` with `superseded_by` set to R3; R3 is `active` with `supersedes` set to R2.
4. Confirm the same section now retrieves R3 and no longer retrieves R2's chunks.
