## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocker] pdf-parse not installed**
- **Found during:** Task 1
- **Issue:** The Deno CLI imported pdf-parse via `npm:pdf-parse/lib/pdf-parse.js` (Deno fetches npm at runtime). Under tsx/Node it must be a declared dependency — it was neither declared nor installed.
- **Fix:** `npm install pdf-parse @types/pdf-parse`.
- **Verification:** import resolves; tests + no-args CLI run under tsx.
- **Committed in:** `77e2299`

**2. [Rule 1 - Correctness] pdf-parse v2 API differs from the plan's assumed v1 default-export**
- **Issue:** The plan assumed `import pdfParse from 'pdf-parse'; pdfParse(buffer)` (v1 API). The installed latest (v2.4.5) exports a `PDFParse` class, not a default function.
- **Fix:** Used `import { PDFParse } from 'pdf-parse'` → `new PDFParse({ data: buffer }).getText()` → `.text`, with `.destroy()` cleanup.
- **Verification:** Import resolves; grep criterion (`pdf-parse` present) satisfied; real PDF parse exercised in Plan 07.

**3. [Rule 2 - Missing critical] --agency made required**
- **Issue:** `regulatory_documents.agency` is NOT NULL; the plan's required set omitted `--agency`, so a run without it would fail the RPC insert.
- **Fix:** Added `--agency` to the required set (also matches the original Deno CLI). Test coverage for the two plan-specified required flags (document-key, geography) unaffected.

**Note on TDD:** Task 1 was `tdd=true`, but as a port the plan structured tests as a separate Task 2; implementation preceded the (updated) tests, which now pass GREEN. RED-first was not meaningful for porting existing behavior.
