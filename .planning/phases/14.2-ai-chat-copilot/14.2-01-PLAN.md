**`supabase/migrations/20260515000040_chat_sessions_realtime.sql`**:

This migration adds `chat_sessions` to the Supabase Realtime publication so that `pending_actions` and `active_task` updates are broadcast to subscribed clients. First verify the table isn't already in the publication — if the project's other migrations already added it, this is a no-op migration (add a comment explaining why).

Migration content:
```sql
-- Phase 14.2: Enable Realtime on chat_sessions for pending_actions and active_task live updates.
-- Required for ActionQueue (Part B) to update reactively without polling.

-- Check if already present; only add if absent (idempotent approach via DO block)
DO $$
BEGIN
  IF NOT EXISTS (
    SELECT 1 FROM pg_publication_tables
    WHERE pubname = 'supabase_realtime'
      AND tablename = 'chat_sessions'
  ) THEN
    ALTER PUBLICATION supabase_realtime ADD TABLE chat_sessions;
  END IF;
END;
$$;

-- Also enable replica identity FULL so Realtime receives the full row on UPDATE
-- (required for payload.new to include JSONB columns like pending_actions)
ALTER TABLE chat_sessions REPLICA IDENTITY FULL;
```

The `REPLICA IDENTITY FULL` line is critical — without it, Supabase Realtime only sends the changed columns' primary key on UPDATE, not the full JSONB payload. This ensures `payload.new.pending_actions` is populated.

Push the migration: `supabase db push` (requires Supabase CLI). If the executor cannot push (auth gate), note it as a checkpoint for the user to push manually, but write the file regardless.
