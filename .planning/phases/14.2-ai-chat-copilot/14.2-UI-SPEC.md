## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge inner padding, chip gap |
| sm | 8px | Button padding (px-2 py-1), card inner spacing |
| md | 16px | Card padding, section gaps within panel |
| lg | 24px | Panel section breaks |
| xl | 32px | Layout gaps between major panel regions |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Ghost decoration widget: `py-1.5 px-2.5` (6px/10px) matches existing `AskUserCard` input field — consistent with existing compact chat affordances
- Touch targets for Accept/Reject buttons in ghost widgets: minimum 44px height (accessibility requirement, D-08/D-09)
- Badge chip (change type label): `px-1.5 py-0.5` (6px/2px) — compact by design, muted visual weight

## Copywriting Contract

### Ghost Decoration Badges (D-08, D-09, D-10)

| Change Type | Badge Text | aria-label |
|-------------|------------|------------|
| replace | EDIT | "Proposed edit replacing the following paragraph" |
| insert_after | INSERT | "Proposed new paragraph to insert here" |
| delete | DELETE | "Proposed deletion of the following paragraph" |

Badge style: uppercase, `text-[10px] font-medium tracking-wide`, muted color matching decoration family (amber for EDIT, red for DELETE, jamo-400 for INSERT). Positioned top-left of widget decoration.

Source: `CHANGE_TYPE_LABELS` typed mapping — defined in same file as `TOOL_STATUS_LABELS` (D-10).

|--------|-------|-------|

### Action Queue (Part B)

| Element | Copy |
|---------|------|
| Queue section header | "Suggestions" |
| Empty queue | "No suggestions right now. Ask me anything below." — muted gray, no icon, low visual weight (D-17) |
| Collapsed queue header | "N items in queue" + expand chevron affordance (D-16) |
| Queue overflow footer | "+N more — focus on these first" — clickable, expands inline (D-27) |
| Dismissed items toggle | "N dismissed" — collapsed by default, chevron to expand (D-24) |

| Active walkthrough queue item | "Continue [section_title] walkthrough" — high-priority, accent styling (D-39) |

Queue item text format (D-29): "[Section Name] — [description of issue]"

Section name is visible in item text, never in tooltip.

Queue item type badge colors:
- `compliance` — `bg-red-50 text-red-700 text-[10px]`
- `conflict` — `bg-amber-50 text-amber-700 text-[10px]`
- `gap` — `bg-blue-50 text-blue-700 text-[10px]`
- `missing` — `bg-gray-100 text-gray-600 text-[10px]`

| Drift detected | "Content has changed since this walkthrough started — restart or discard?" |

| Element | Copy |
|---------|------|
| Button label | "Stop walkthrough" — never "Cancel" (D-41) |
| Inline clarification | "Accepted changes will stay in your document." |
| Terminal summary | "Walkthrough stopped — N changes kept, M not reviewed." |

### Primary CTAs

| CTA | Label | Context |
|-----|-------|---------|
| Primary (ghost) | "Accept" | Per-change affordance in editor |
| Primary (queue) | "Start review" | Queue item CTA — opens walkthrough |
| Primary (resume) | "Continue" | Continue walkthrough queue item |
| Dismiss (queue) | "Dismiss" | Single click, no confirmation (D-23) |
| Undo dismiss | "Undo" | Inline, appears immediately after dismiss |

### Error States

| Scenario | Copy |
|----------|------|
| Analysis fetch failure | Silent — queue stays empty. No error surfaced to user (per RESEARCH.md edge function pattern: validation failure returns empty array) |
| Accept/Reject write failure | Toast: "Change saved locally. Sync failed — will retry." (D-15 fire-and-forget + retry queue) |
| Stop walkthrough write failure | Optimistic clear proceeds. Toast: "Walkthrough stopped. Sync failed — will retry." (D-43) |
| Drift on resume | "Content has changed since this walkthrough started — restart or discard?" (not an error — a decision prompt) |

### Empty States

| Surface | Copy |
|---------|------|
| Action queue (no items) | "No suggestions right now. Ask me anything below." |
| EditSummaryCard drill-down (0 changes) | Not reachable — card only renders when changes exist |
| Dismissed items (0 dismissed) | Collapsed section not shown — only visible when dismissed count > 0 |

### Destructive Actions

| Action | Confirmation Approach |
|--------|-----------------------|
| "Discard walkthrough" (drift resume) | Inline two-button prompt: "Restart" / "Discard walkthrough" — no modal, no separate confirmation step |
| "Reject" on ghost decoration | No confirmation — immediate, reversible via Reject All undo or undo history (single ProseMirror transaction) |
| "Reject All" in EditSummaryCard | No confirmation — immediate, one undo step |

## Interaction Contracts

### Ghost Decoration Behavior

- Ghost widget renders **below** source paragraph as a widget decoration (not in document)
- Source paragraph receives node decoration class: `pending-edit-source pending-edit-{modify|delete}`
- Accept/Reject buttons minimum 44px touch target height (accessibility)
- On Accept: source paragraph content replaced, both decorations removed, tally updates optimistically
- On Reject: both decorations removed, source paragraph unchanged
- On anchor paragraph edit/delete: decoration auto-rejects with `auto_rejected_stale`, immediate visual removal, no disabled/stale state left on screen (D-04)
- Ghost content **never** appears in `editor.getHTML()` — decorations are view-only

### Action Queue Behavior

- Renders above chat history in message list area (D-16, confirmed from RESEARCH.md open question resolution)
- Collapses (not disappears) when walkthrough starts — header shows "N items in queue" + expand chevron
- Cap: 8 visible items. Per-tier: max 4 compliance, 2 conflict, 2 gap, 2 missing (D-26)
- Dismiss: single click, no confirmation. Dismissed item moves out of active list immediately (D-23)
- Undo affordance: inline "Undo" appears immediately after dismiss, disappears after 5 seconds
- "+N more" footer expands inline, collapses automatically when queue drops to ≤8 (D-27)

### Transitions

- Queue item dismiss: `transition-all duration-150` slide-out or fade (framer-motion available)
- Card terminal state desaturation: no animation — instant visual state change on final resolution
- Queue collapse/expand: smooth height transition via framer-motion `AnimatePresence`
- Button tactile feedback: inherited from global `button:active { transform: scale(0.97) }` in index.css
