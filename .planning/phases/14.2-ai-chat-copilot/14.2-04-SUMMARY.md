## What Was Built

### Task 1 — Pure Reducer Extensions

Added `buildResolutionMap` exported helper and 6 new pure reducer cases to `SectionWorkspaceContext.tsx`:

- `SET_PENDING_EDITS` — replaces section pending_edits, forces all incoming resolutions to `'pending'`
- `ACCEPT_PENDING_EDIT` — sets matched paragraph to `'accepted'`, others unchanged
- `REJECT_PENDING_EDIT` — sets matched paragraph to `'rejected'`, others unchanged
- `CLEAR_PENDING_EDITS` — empties the pending_edits array for a section
- `AUTO_REJECT_STALE_EDITS` — sets stale_ids to `'auto_rejected_stale'`; includes trigger-path comment (plugin staleness detection → queueMicrotask → SectionEditorBlock effect → dispatch)
- `BATCH_ACCEPT_PENDING_EDITS` — accepts only edits with `resolution === 'pending'`; already-resolved edits are SILENTLY SKIPPED (not an error)

Reducer is pure: no `async`, no `supabase.from()`, no side effects inside any switch case.

### Task 2 — usePendingEditsSync Hook

Created `src/hooks/usePendingEditsSync.ts`:

- `useEffect`-based observer on `pendingEdits` + `messageId`
- **Read-modify-write pattern**: `select('tool_data')` then merge `resolutions` key then `update({ tool_data: merged })` — prevents clobbering `payload`/`version` fields
- **Fingerprint ref**: `paragraph_id:resolution` joined string prevents redundant writes when state re-renders with same resolutions
- **Early exit**: skips DB write if all edits still have `resolution === 'pending'`
- **Fire-and-forget**: silent `catch` block per D-15
