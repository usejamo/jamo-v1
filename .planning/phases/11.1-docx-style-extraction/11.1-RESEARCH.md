## Summary

Phase 11.1 has three independent workstreams that can be planned and implemented in parallel: (1) client-side JSZip post-processing of the generated DOCX to inject template styles, (2) extending the existing `template-extract` Edge Function to perform style name inspection and persist the result, and (3) surface changes — 10MB upload cap in TemplatesTab and `style_inspection` warnings in the template list.

The codebase is well-prepared. `exportDocx.ts` already calls `Packer.toBlob()` and triggers a download — the injection point for `applyTemplateStyles()` is unambiguous (between line 138 `Packer.toBlob` and line 139 `createObjectURL`). The `template-extract` Edge Function is a clean Deno function with a well-structured try/catch — adding a style inspection step at position 8.5 (after section insert, before final `ready` update) is straightforward. The `templates` table schema is fully known from migration `20260418000023`.

The one blocking gap: **JSZip is not installed** (`NOT FOUND` in package.json). It must be added as a dependency in Wave 0. The `docx` package (v9.6.1) outputs a standard ZIP blob via `Packer.toBlob()` which JSZip can open without any special handling.

**Primary recommendation:** Wave 0 = install JSZip + migration + test stubs. Wave 1 = `applyTemplateStyles()` utility + export wiring + TemplatesTab cap. Wave 2 = Edge Function style inspection + warning UI. Wave 3 = discoverability nudge.

### Pattern 1: JSZip XML Swap (`applyTemplateStyles`)

**What:** Open both ZIPs, copy three XML entries from template into generated DOCX, repack.
**When to use:** After `Packer.toBlob()`, before `createObjectURL`.

```typescript
// Source: JSZip docs + D-01/D-02/D-03 decisions
import JSZip from 'jszip'

export async function applyTemplateStyles(
  generated: Blob,
  template: Blob
): Promise<Blob> {
  const FILES_TO_SWAP = [
    'word/styles.xml',
    'word/theme/theme1.xml',
    'word/numbering.xml',
  ]
  try {
    const [genZip, tplZip] = await Promise.all([
      JSZip.loadAsync(generated),
      JSZip.loadAsync(template),
    ])
    for (const path of FILES_TO_SWAP) {
      const tplFile = tplZip.file(path)
      if (!tplFile) continue  // template may lack word/numbering.xml — skip gracefully
      const content = await tplFile.async('uint8array')
      genZip.file(path, content)
    }
    return await genZip.generateAsync({ type: 'blob' })
  } catch (err) {
    console.error('[applyTemplateStyles] failed, returning original:', err)
    return generated  // D-03: never fail the export
  }
}
```

**JSZip async API notes:** [VERIFIED: JSZip 3.x docs]
- `JSZip.loadAsync(blob)` returns `Promise<JSZip>` — must await
- `file(path)` returns `null` if entry absent (not an error)
- `async('uint8array')` is the correct extraction method for binary XML
- `generateAsync({ type: 'blob' })` returns `Promise<Blob>` — compatible with `URL.createObjectURL`
- The `docx` package's `Packer.toBlob()` output is a standard ZIP — no special handling needed [ASSUMED: based on docx package behavior; standard OOXML format]

### Pattern 3: Style Inspection in Edge Function

```typescript
// Add to template-extract/index.ts after section insert, before ready update
// Only runs for DOCX files
async function inspectDocxStyles(buffer: ArrayBuffer): Promise<{ found: string[], missing: string[] } | null> {
  const REQUIRED_STYLES = ['Normal', 'Heading 1', 'Heading 2', 'Heading 3']
  try {
    const { default: JSZip } = await import('https://esm.sh/jszip@3.10.1')
    const zip = await JSZip.loadAsync(buffer)
    const stylesFile = zip.file('word/styles.xml')
    if (!stylesFile) return null
    const xml = await stylesFile.async('text')
    // Extract w:styleId attributes from the XML
    const foundIds = [...xml.matchAll(/w:styleId="([^"]+)"/g)].map(m => m[1])
    // Also check w:name w:val for display names
    const foundNames = [...xml.matchAll(/w:name w:val="([^"]+)"/g)].map(m => m[1])
    const allFound = [...new Set([...foundIds, ...foundNames])]
    const found = REQUIRED_STYLES.filter(s => 
      allFound.some(f => f.toLowerCase() === s.toLowerCase())
    )
    const missing = REQUIRED_STYLES.filter(s => !found.includes(s))
    return { found, missing }
  } catch {
    return null  // D-06: malformed XML → null, not false positive
  }
}
```

Note: JSZip is available on `esm.sh` for Deno Edge Functions — same pattern as `mammoth` and `unpdf` already used in this function. [VERIFIED: existing template-extract/index.ts import patterns]

### Anti-Patterns to Avoid

- **Swapping only `styles.xml`:** Styles reference theme colors/fonts via `word/theme/theme1.xml`. Without the theme swap, font and color references break silently — the DOCX opens but looks wrong. Always swap all three files. [D-02]
- **Running inspection client-side on every Settings load:** Re-fetches and decompresses the template for every user who opens Settings. Edge Function inspection at upload time is free (file already open). [D-04]
- **Failing the export on template fetch error:** Network blip, expired signed URL, or storage permission issue must all fall through to the Calibri-defaults export, not show an error. [D-03]
- **Soft warning on 10MB breach:** User gets a degraded export at the end of a long workflow. Hard reject at upload with clear message is better UX. [D-16]
- **Using `file.async('string')` for XML swap:** Use `uint8array` — XML files may contain non-UTF8 encoding declarations; binary copy is safe.

## Common Pitfalls

### Pitfall 1: `word/numbering.xml` May Be Absent
**What goes wrong:** `tplZip.file('word/numbering.xml')` returns `null` — template has no custom numbering. Code throws or writes `null` into the ZIP.
**Why it happens:** Simple templates without lists often omit `numbering.xml`. It is an optional OOXML part.
**How to avoid:** Always check `if (!tplFile) continue` before copying. The generated DOCX's own numbering (bullet-list, number-list from `exportDocx.ts`) remains intact.
**Warning signs:** Export succeeds but bullets disappear or are malformed.

### Pitfall 2: Style Name Case Sensitivity in Inspection
**What goes wrong:** Word style names are case-insensitive in the UI but stored with specific casing in XML (`styleId="Heading1"` vs display name `"Heading 1"`). A naive string match misses them.
**Why it happens:** OOXML uses both `w:styleId` (camelCase, no spaces) and `w:name w:val` (display name with spaces). "Heading 1" has styleId `Heading1`.
**How to avoid:** Check both `w:styleId` and `w:name w:val` with case-insensitive comparison.
**Warning signs:** Inspection reports `Heading 1` as missing from a template that clearly has it.

### Pitfall 3: RLS on `templates` UPDATE from Edge Function
**What goes wrong:** Edge Function tries to write `style_inspection` to the templates row and gets a 403.
**Why it happens:** The `templates_update_admin` RLS policy requires the caller to be an admin user. Edge Functions using `SUPABASE_SERVICE_ROLE_KEY` bypass RLS — but only if the client is created with the service role key.
**How to avoid:** Confirm `template-extract/index.ts` uses `SUPABASE_SERVICE_ROLE_KEY` (it does — line 161). No RLS change needed.
**Warning signs:** `style_inspection` column remains `null` after upload even when the file is valid.

### Pitfall 4: JSZip `generateAsync` Output vs `Packer.toBlob` Output
**What goes wrong:** The repackaged DOCX fails to open in Word with a "corrupt file" error.
**Why it happens:** `JSZip.generateAsync` defaults may alter compression settings. Some OOXML validators are sensitive to ZIP structure differences.
**How to avoid:** Use `{ type: 'blob', compression: 'DEFLATE', compressionOptions: { level: 6 } }` or just `{ type: 'blob' }` (JSZip default is DEFLATE). The `docx` package does not require a specific compression level. [ASSUMED: based on JSZip docs; should be validated with a real template during implementation]
**Warning signs:** File downloads but Word reports "repaired content" on open.

### Pitfall 5: 10MB Check Missing for Drag-and-Drop
**What goes wrong:** File input `onChange` gets the size check, but drag-and-drop `onDrop` bypasses it.
**Why it happens:** Both paths call `handleFileUpload(file)` in `TemplatesTab.tsx` — add the check once inside `handleFileUpload`, not in `onFileInputChange` and `onDrop` separately.
**How to avoid:** The single check in `handleFileUpload` (line 303) covers both paths — confirmed by reading the component.
**Warning signs:** Large PDF files slip through via drag-and-drop.
