# Phase 14.2.1 Plan 01: useGapAnalysisTrigger Hook Summary

**One-liner:** Extracted the dead Part B trigger wiring (`AIChatPanel.tsx:228-242 void triggerAnalysis`) into a reusable `useGapAnalysisTrigger` hook that owns D-30 Realtime debounce, D-35 initial-population, content-hash skip, and 429-silence.

## What shipped

`src/hooks/useGapAnalysisTrigger.ts` — fire-and-forget hook with signature `useGapAnalysisTrigger({ proposalId, userId }): void`. Internals:

- **D-35 initial fire:** on mount with valid (proposalId, userId), `supabase.from('chat_sessions').select('id').eq(proposal_id).eq(user_id).maybeSingle()`. If `data === null`, fetch all `proposal_sections`, force-invoke `analyze-proposal-gaps` once.
- **D-30 Realtime trigger:** subscribes to `gap_analysis_sections:${proposalId}` channel for `postgres_changes` UPDATE events on `proposal_sections` with filter `proposal_id=eq.${proposalId}`. Each event resets a `setTimeout(..., 3000)`. After the debounce, fetches the **full** current `proposal_sections` rows from the DB (never reads `payload.new` for content), computes SHA-256 of sorted summaries, skips if the hash matches the prior run, otherwise invokes.
- **Run-ID per call:** `globalThis.crypto.randomUUID()` in each body.
- **In-flight guard:** `isAnalyzingRef` boolean ref prevents overlapping invokes.
- **429 silence:** detects `error.context.status === 429`, `error.status === 429`, or `/\b429\b/.test(error.message)` — no console output. Other errors → `console.debug` only.
- **Cleanup:** clears the debounce timer, calls `supabase.removeChannel(channel)`, sets a `cancelled` flag so any in-flight IIFE bails before invoking after unmount.
- **Proposal switch reset:** a dedicated effect on `[proposalId]` resets `hashRef.current = null` and clears the debounce timer, so switching proposals starts with a fresh hash.

`src/hooks/__tests__/useGapAnalysisTrigger.spec.ts` — 7 Vitest tests proving every must_have:

1. Initial fire when no chat_sessions row → exactly one invoke with sorted sections and a UUIDv4 `run_id`.
2. Initial skip when chat_sessions row exists → zero invokes.
3. Debounce coalescing: 5 rapid Realtime events within 100ms each + 3000ms advance → exactly one invoke.
4. Content-hash skip: identical content twice → still one invoke; changed content → second invoke fires.
5. 429 silence: invoke result returns `{ error: { context: { status: 429 } } }` → no `console.error`, no `console.debug`.
6. Unmount cleanup: `supabase.removeChannel` called once; debounced timer queued before unmount does not fire after.
7. proposalId change: rerender with new pid → initial-population check runs again for the new proposal.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Test isolation: pending IIFE from prior test bled invoke calls into the next test**
- **Found during:** Task 2 verification
- **Issue:** With `pool: 'forks', singleFork: true` and the hook's async IIFE (maybeSingle → fetchSummaries → `crypto.subtle.digest` → invoke), `Promise.resolve()` microtask flushing alone was not enough to settle the chain inside a single test. The unresolved invoke from test 1 was firing during test 2 against test 2's spy, breaking the "skip" assertion.
- **Fix:** `flushAsync()` now interleaves `setTimeout(0)` macrotasks with `Promise.resolve()` microtasks (10 outer iterations × 20 inner microtasks). This drains the `crypto.subtle.digest` chain reliably under happy-dom. Tests using `vi.useFakeTimers()` use a separate `advanceAndFlush(ms)` helper that pumps both timer ticks and microtasks.
- **Files modified:** src/hooks/__tests__/useGapAnalysisTrigger.spec.ts (flushAsync helper)
- **Commit:** 21fe0ae

**2. [Rule 1 - Bug] `vi.restoreAllMocks()` was nuking factory-level vi.fn implementations**
- **Found during:** Task 2 verification
- **Issue:** Initial test scaffolding used `vi.fn()` inside the `vi.mock` factory for `supabase.from`, `.channel`, `.functions.invoke`. After the first test, `afterEach → vi.restoreAllMocks()` was clearing those implementations, so the next test got `undefined` from `from().select().eq().maybeSingle()`.
- **Fix:** Rewrote the mock factory to use plain JS functions for the supabase client surface (no `vi.fn` inside the factory). Per-test spies (invokeSpy, removeChannelSpy, subscribeSpy) live on a module-level `mockState` object and are re-armed in `beforeEach → resetMockState()`. `afterEach` does `cleanup()` + drain microtasks + `vi.clearAllMocks()` only.
- **Files modified:** src/hooks/__tests__/useGapAnalysisTrigger.spec.ts (mock factory + afterEach)
- **Commit:** 21fe0ae
