<objective>
Build the three standalone auth pages: `/accept-invite` (invitee sets initial password, req 5), the forgot-password request page, and `/reset-password` (req 10). Critically, each flow is identified by its ROUTE, never by inspecting auth state (Pitfalls 1/2 — invite links carry no distinguishing event).

Purpose: The invite link and reset link both establish an implicit-flow session the instant they're clicked, BEFORE a password is set; these dedicated routes force the set-password step. Routing is wired later in plan 11; these are the leaf pages.
Output: Three auth page components + a ResetPassword unit test.

| T-15-10 | Information Disclosure | ForgotPassword | mitigate | Static "if an account exists" confirmation — no user enumeration signal. |
| T-15-11 | Information Disclosure | invalid/expired link | accept | Generic invalid-link copy directs to admin/self-request; no token detail leaked. |
