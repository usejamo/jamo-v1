Solve the chicken-and-egg: a committed, idempotent Node/tsx script that provisions the initial platform `super_admin` (D-12 / req 11). It upserts an internal org, inserts a PENDING bootstrap invite, calls `auth.admin.createUser` (the plan-01 trigger binds via the single invites-reading path), then flips the invite to `accepted`. Skips entirely if a super_admin already exists.

Purpose: `/admin` is unreachable with no super_admin. This artifact makes a fresh environment reachable reproducibly, using the exact same invite-first flow as every other provisioning path (no special trigger branch).

```ts
const admin = createClient(SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, { auth: { persistSession: false } })
const { data: existing } = await admin.from('user_profiles').select('id').eq('role','super_admin').limit(1)
if (existing?.length) { console.log('super_admin already exists, skipping'); process.exit(0) }
const { data: org } = await admin.from('organizations')
  .upsert({ name:'Jamo Internal', slug:'jamo-internal', plan:'internal' }, { onConflict:'slug' }).select().single()
const email = env.BOOTSTRAP_SUPER_ADMIN_EMAIL, password = env.BOOTSTRAP_SUPER_ADMIN_PASSWORD
const { data: invite } = await admin.from('invites')
  .insert({ email, org_id: org.id, role:'super_admin', status:'pending' }).select().single()
const { error } = await admin.auth.admin.createUser({ email, password, email_confirm:true })
if (error) throw error
await admin.from('invites').update({ status:'accepted' }).eq('id', invite.id)
```
NOTE: seed-regulatory uses Node/tsx (`process.exit`, `npx tsx`), NOT Deno — follow that convention.
