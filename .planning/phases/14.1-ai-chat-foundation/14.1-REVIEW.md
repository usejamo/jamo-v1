# Phase 14.1 Code Review — AI Chat Foundation

## Summary

The tool-use SSE architecture is well-structured and the RLS policies are correct. Two critical bugs need fixing before this ships to production: the SSE stream has no cancellation mechanism on component unmount (causes state updates on unmounted components and wasted Anthropic API spend), and `persistToolDataState` has a stale-closure bug that silently drops DB updates when called rapidly. Five warnings cover real but non-crashing problems.

---

## CRITICAL

### C-01 — No AbortController on SSE fetch; stream continues after unmount

**File:** `src/components/AIChatPanel.tsx` — `handleSubmit`

The raw `fetch()` to `chat-with-jamo` has no `signal` attached and the `reader` is never cancelled. If the user navigates away while a stream is in progress, the `while(true)` read loop keeps running, calling `setMessages`, `setStreamingContent`, and `setIsStreaming` on an unmounted component. This also keeps the Anthropic stream open, burning API tokens with no user.

**Fix:** Create an `AbortController` ref (e.g. `streamAbortRef`), attach `signal` to the `fetch` call, and cancel in a `useEffect` cleanup:

```ts
// On mount / each send:
streamAbortRef.current?.abort()
streamAbortRef.current = new AbortController()

const response = await fetch(url, { ..., signal: streamAbortRef.current.signal })

// useEffect cleanup:
useEffect(() => () => { streamAbortRef.current?.abort() }, [])
```

Also call `reader.cancel()` in the catch block when the error is an `AbortError`.

### C-02 — Stale closure in `persistToolDataState` causes silent lost DB writes

**File:** `src/components/AIChatPanel.tsx` — `persistToolDataState`

```ts
const persistToolDataState = useCallback(async (messageId: string, newState: ...) => {
  const msg = messages.find(m => m.id === messageId)  // ← captures stale messages
  ...
}, [messages])
```

`messages` is in the dependency array, so the callback is recreated on every render. Any child component (ComplianceCard, DiffPreview) that holds a reference to a prior version of `persistToolDataState` calls into stale state where `messages.find()` returns `undefined`, causing a silent early-return. The DB update never fires.

**Fix:** Use a `useRef` to hold a live reference to `messages`:

```ts
const messagesRef = useRef(messages)
useEffect(() => { messagesRef.current = messages }, [messages])

const persistToolDataState = useCallback(async (messageId, newState) => {
  const msg = messagesRef.current.find(m => m.id === messageId)
  ...
}, [])   // stable identity; child callbacks never stale
```

## WARNING

### W-01 — Edge function does not verify caller's `org_id` against the JWT

**File:** `supabase/functions/chat-with-jamo/index.ts`

The function receives `org_id` from the POST body and passes it to RAG, DB writes, and tool handlers. It never verifies that the caller's JWT actually belongs to that `org_id`. A user in org A can claim `org_id` of org B and read org B's RAG context.

```ts
// No check like:
const { data: { user } } = await supabase.auth.getUser()
const jwtOrgId = user?.user_metadata?.org_id ?? user?.app_metadata?.org_id
if (jwtOrgId !== org_id) return 401
```

RLS on `proposal_chats` and `chat_sessions` protects writes, but RAG retrieval (`fetchRagContext(org_id, ...)`) uses the anon key with no per-org guard — it queries by the caller-supplied `org_id` directly.

**Fix:** Extract `org_id` from the verified JWT rather than from the request body, or add an explicit cross-check before any data access.

---

### W-02 — `handleCheckCompliance` passes `proposal_id` and `org_id` from client body to a service-role DB write without validation

**File:** `supabase/functions/chat-with-jamo/tools/check-regulatory-compliance.ts`

`handleCheckCompliance` receives `proposalId` and `orgId` (sourced from the unverified request body — see W-01) and writes compliance flags to `proposal_sections` using the **service role key**, which bypasses RLS entirely. A malicious caller can supply an arbitrary `proposalId` and permanently corrupt another org's compliance flags.

This is more severe than W-01 because the service role key makes RLS irrelevant for this write path.

**Fix:** Same root fix as W-01 (extract org from JWT). Additionally, validate that the `proposalId` belongs to the caller's org before the service-role write.

### W-03 — Keyboard shortcut `useEffect` suppresses exhaustive-deps with empty array; stale `handlePanelToggle` closure

**File:** `src/components/AIChatPanel.tsx`

```ts
useEffect(() => {
  const handler = (e: KeyboardEvent) => { ... handlePanelToggle() }
  document.addEventListener('keydown', handler)
  return () => document.removeEventListener('keydown', handler)
}, []) // eslint-disable-line react-hooks/exhaustive-deps
```

`handlePanelToggle` is declared as a plain function (not `useCallback`) inside the component. The effect captures the initial instance, so after the first render the keyboard shortcut always calls the stale `handlePanelToggle` — which reads stale `gapCount`, `gapMessagesInjected`, and calls a stale `injectGapMessages`. The panel toggle itself still works (it uses a functional updater for `setExpanded`), but the gap-injection branch inside it will silently mis-fire.

**Fix:** Wrap `handlePanelToggle` in `useCallback` with correct deps, then include it in the effect dep array. Or convert the effect to use a ref callback pattern.

### W-04 — SSE chunk boundary splitting can drop `data:` lines

**File:** `src/components/AIChatPanel.tsx` — `handleSubmit` SSE loop

```ts
const chunk = decoder.decode(value, { stream: true })
const lines = chunk.split('\n').filter(line => line.startsWith('data: '))
```

SSE events are newline-delimited. A TCP chunk can split an event across two `reader.read()` calls (e.g. `data: {"type":"tool_r` / `esult",...}\n\n`). The current code discards the partial first line and the continuation starts with `esult"` which does not pass the `startsWith('data: ')` filter — the `tool_result` event is silently dropped. The tool result card never renders, even though streaming succeeds.

This is latent today because tool results tend to be small, but it is a real protocol bug.

**Fix:** Maintain a line buffer across `read()` calls:

```ts
let lineBuffer = ''
// inside while(true):
lineBuffer += decoder.decode(value, { stream: true })
const lines = lineBuffer.split('\n')
lineBuffer = lines.pop() ?? ''   // keep incomplete last line
for (const line of lines) { if (line.startsWith('data: ')) { ... } }
```

### W-05 — `tool_data` JSONB column has no migration-level check constraint; any shape accepted silently

**File:** `supabase/migrations/20260512000031_chat_tool_data.sql`

The `tool_data` column is a bare `JSONB DEFAULT NULL` with no `CHECK` constraint on the required `version` field or `tool` discriminator. A write with malformed shape (e.g. missing `version`) will succeed at the DB level. On history load, `AIChatPanel` guards with `if (td.version !== 1) return undefined`, but that silently discards the message's tool card — the user sees a plain chat bubble instead of the DiffPreview / ComplianceCard they expected.

**Fix (optional for now, recommend for next migration):** Add a check constraint:

```sql
ALTER TABLE proposal_chats
  ADD CONSTRAINT tool_data_version_check
  CHECK (tool_data IS NULL OR (tool_data->>'version') = '1');
```

Or add a `jsonschema_is_valid` check if the pg_jsonschema extension is available.

## INFO

### I-01 — `detectGaps` in `chatContext.ts` uses raw `section_key` string as gap title instead of `sectionKeyToTitle`

**File:** `src/utils/chatContext.ts`

```ts
const sectionTitle = section.section_key   // ← raw key, not title
gaps.push({ sectionTitle, ... })
```

`sectionKeyToTitle` is defined in the same file but not called here. Gap messages surfaced in the chat panel display the raw key (e.g. `"study_understanding"`) instead of `"Study Understanding"`.

**Fix:** Replace with `sectionKeyToTitle(section.section_key)`.

### I-02 — `chat_history` sent to the edge function includes full `tool_data` blobs from history load

**File:** `src/utils/chatContext.ts` — `buildContextPayload`

The chat history payload passes `ChatMessage[]` from component state. Those messages include `toolData` (the full ToolDataEnvelope). `buildHistory` in `context.ts` maps only `role` and `content`, so the extra data is not sent to Claude — but the serialized payload to the edge function is larger than necessary, and any future change to `buildContextPayload` that includes `toolData` could accidentally send large diffs to the Anthropic API.

**Recommendation:** Explicitly strip `toolData` when building the history payload in `buildContextPayload`.

### I-03 — `handleSetFocus` silently swallows upsert errors; broken session state gives no signal

**File:** `supabase/functions/chat-with-jamo/tools/set-focus.ts`

```ts
await supabase.from("chat_sessions").upsert(...).select()
// Silence — no error check
```

If the upsert fails (network, constraint violation, service key misconfigured), `set_focus` still returns `{ section_key }` to the client as a success. The client updates its UI focus, but the DB session state is stale. Subsequent tool calls that rely on `current_focus_section` will operate on the wrong section.

**Fix:** Check the upsert error and include it in the returned payload so `index.ts` can emit a warning SSE event.

---

### I-04 — `response.body!` non-null assertion will throw if fetch returns a response with no body (e.g. 204 or edge network layer strips body)

**File:** `src/components/AIChatPanel.tsx` — `handleSubmit`

```ts
const reader = response.body!.getReader()
```

The `!` assertion bypasses the null check. If `response.body` is null (some proxies and certain Supabase error responses do not include a body), this throws a `TypeError: Cannot read properties of null` which is caught by the outer `catch` and shown as a generic error — but the user never sees what went wrong.

**Fix:** Add an explicit check: `if (!response.body) throw new Error('No response body from edge function')`.

## Architecture Notes (No Action Required)

- **CORS wildcard** (`Access-Control-Allow-Origin: "*"`) is correct for a Supabase edge function accessed from the browser; authorization is handled by the JWT Bearer token, not origin restriction.
- **`chat_sessions` RLS** (`org_id = (auth.jwt() ->> 'org_id')::uuid`) is correctly structured. The service-role writes in `set-focus.ts` and `check-regulatory-compliance.ts` intentionally bypass this — acceptable as long as W-01/W-02 are fixed so the `org_id` being written is trusted.
- **`tool_data` version guard** on history load (`if (td.version !== 1) return undefined`) is a good forward-compatibility pattern; keep it.
- **`handleProposeEdit`, `handleAnswerWithCitations`, `handleAskUser`** are all pure synchronous functions that just return the validated input — correct for tools that have no server-side side effects.
- **SSE `[DONE]` sentinel** and `controller.close()` pattern is correct; the `[DONE]` line is emitted even on stream error (inside the catch/finally), which ensures the client always exits the read loop cleanly.
