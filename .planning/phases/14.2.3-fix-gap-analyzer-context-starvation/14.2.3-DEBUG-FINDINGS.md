**① Cache-trap — FIXED + shipped.**
- Mount gate skipped re-analysis on hash-match without checking pending_actions emptiness;
  edge persisted the hash even for `[]`. So `[] + matching hash` cached empty forever.
- Fix committed: client gate now skips only when hash matches AND pending_actions non-empty
  (`useGapAnalysisTrigger.ts`); edge persists hash only when `pendingActions.length > 0`
  (`analyze-proposal-gaps/index.ts`). RED/GREEN test added. Commits **c3c767a** (edge) +
  **95eaf6d** (client). Verified live: trapped rows' `has_hash` flipped true→false.

**② Resolved-block over-suppression — ROOT CAUSE CONFIRMED, real fix NOT yet shipped.**
- The `RESOLVED_ITEMS` block (8 full JSON entries + suppression instructions injected into the
  system prompt) makes Haiku go GLOBALLY silent — returns `[]` even for untouched,
  placeholder-laden sections.
- First attempt (prompt counterweight wording, in commit c3c767a) FAILED — v9 still returned `[]`.
- DECISIVE A/B (TEMP commit **0ff3389**, deployed as v10): with the resolved block REMOVED,
  bfb0b16d went **0 → 5 findings**, including untouched sections 4 & 9. → the block is the cause.
  Not Zod-collapse (action_count came back valid), not base prompt.
