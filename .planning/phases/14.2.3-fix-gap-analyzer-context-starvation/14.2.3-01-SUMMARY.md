# Phase 14.2.3 Plan 01: Gap Analyzer Context Starvation Fix (Edge-Function Changes) Summary

Three independent edge-function changes that stop the analyzer from hiding section content from Haiku: full section content up to a 5000-char ceiling with a clearly-meta end-marker (D-1), a sharpened placeholder-detection prompt with exactly 4 semantic-family few-shot examples (D-2), and rebalanced tier caps so placeholder-heavy proposals can surface enough findings (D-5). Single-Haiku-call, all-sections structure preserved. No migration, client, or editor changes (those are Plans 02/03).

## What Changed

### Task 1 — Tier caps (D-5)
`QUEUE_CAP` 8 → 10; `TIER_CAPS` `{ compliance: 4, conflict: 2, gap: 2, missing: 2 }` → `{ compliance: 4, conflict: 2, gap: 4, missing: 4 }`. Pure constant swap at index.ts:15–16. Application logic at :308–314 (reads the constants, `.slice(0, QUEUE_CAP)`) untouched.

### Task 2 — Full content + end-marker (D-1)
Replaced the `.slice(0, 300)` step in the excerpt builder. Now computes the cleaned string once (HTML-strip + whitespace-collapse + trim retained verbatim), then branches on a `CONTENT_CEILING = 5000`: sections ≤5000 chars are sent whole; over-ceiling sections are cut at 5000 chars with `TRUNCATION_MARKER = ' […section truncated for length…]'` appended at the END (model reads real content first, then learns the tail is incomplete). No structured `truncated: true` field; no per-section loop; single Haiku call at index.ts:291 unchanged.

**Optional D-1 prompt line: ADDED.** A single line was added to ANALYSIS_SYSTEM_PROMPT (index.ts:125) instructing the model that the truncation marker is meta — judge the section on visible content only, do not infer about the unseen tail, do not flag the marker. This mitigates threat T-1423-03 (marker mistaken for placeholder scaffolding) at near-zero cost.

### Task 3 — 4 placeholder-family few-shots (D-2)
Extended ANALYSIS_SYSTEM_PROMPT (did not replace its structure). Added a semantic-family framing sentence ("recognize the general pattern, not only the exact strings") and the decision boundary (substantive content + placeholders ⇒ gap; predominantly scaffolding ⇒ missing), then exactly 4 category-representative few-shots, one per family:
1. **Bracket** — cover-letter `[CRO Name]` amid real prose ⇒ `gap`
2. **Descriptive-noun** — study-design `investigational product name` / `CRO legal entity name` ⇒ `gap`
3. **Incomplete contact/address** — contacts block of `mailing address` / `full corporate address` / `Name and title of RFP contact` ⇒ `missing` (own anchor, not merged into descriptive-noun)
4. **Explicit marker** — eligibility `TBD — to be determined` ⇒ `missing`

Each example carries a realistic paraphrased CRO fragment, the gap-vs-missing OUTPUT, and a one-line `Rationale:`. All 4 stay inside ANALYSIS_SYSTEM_PROMPT so `buildResolvedBlock` still appends after them at index.ts:308.

**OUTPUT: count for downstream readers — exactly 4.** The original "TBD" → missing few-shot was **folded into the Family 4 (explicit-marker) example** rather than kept separate, so the prompt now has 4 `OUTPUT:` lines total (not 5).
