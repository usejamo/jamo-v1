## Shared Patterns

### SHA-256 hash convention (Decision 6 equality, Acceptance #8)
**Source:** `src/utils/sectionHash.ts:8` (`sha256OfSection`, client) ↔ `index.ts:49` (`sha256Hex`, Deno) — byte-identical algorithm (`crypto.subtle.digest('SHA-256', TextEncoder().encode(input))` → hex). The edge re-hashes `s.content` (`:244–261`) with the same function. The equality the staleness annotation depends on: `sha256OfSection(html_passed_to_saveNow)` (client, resolve-time) === `sha256Hex(s.content)` (edge, later) **iff** the DB content == the hashed string. Flush-then-hash guarantees this.
**Apply to:** resolve handlers (AIChatPanel), do not re-implement hashing inline.

### `saveNow` as the single canonical persist path
**Source:** `useAutosave.ts:46–62`; precedent call `SectionEditorBlock.tsx:354`.
**Apply to:** every resolve-time content commit. Never write `proposal_sections.content` from AIChatPanel directly (bypasses `isEffectivelyEmpty`).

### Fire-and-forget + silent-failure stance
**Source:** `useGapAnalysisTrigger.ts:52–59` (`isSilentStatus`, 429/402 = expected silence) and the existing `void (async () => ...)()` dismiss write (`:723`).
**Apply to:** the resolve sequence — `saveNow` failure logs at `console.debug` and degrades, never throws to the user; the trigger treats cooldown 429 as expected.

### Atomic-write-to-avoid-desync
**Source:** the single `chat_sessions` upsert (`index.ts:339–350`).
**Apply to:** `pending_actions_content_hash` (Decision 3) — same upsert object as `pending_actions`, never a separate statement.
