<objective>
Consolidate the proposal status enum from 5 values to 4 by merging `in_progress` into `draft`.

Rationale: `in_progress` and `draft` represent the same pre-submission state. Having two
draft-like statuses creates confusion in the pipeline view and adds an extra step for users.

After this plan: status union = 'draft' | 'submitted' | 'won' | 'lost'
Draft gets the amber color that in_progress previously held.

Verification: `grep -rn "in_progress" src/` must return 0 matches after execution.
</objective>

<read_first>
- supabase/migrations/20260305000004_proposals.sql (already confirmed: status is TEXT, not ENUM — no ALTER TYPE needed)
</read_first>

<action>
Create supabase/migrations/20260508000030_consolidate_in_progress_to_draft.sql with:

```sql
-- Consolidate in_progress into draft: both represent pre-submission work-in-progress.
-- After this migration the valid status values are: draft, submitted, won, lost.
UPDATE proposals
SET status = 'draft'
WHERE status = 'in_progress';

COMMENT ON COLUMN proposals.status IS 'Valid values: draft, submitted, won, lost';
```

Do NOT modify 20260305000004_proposals.sql — it is historical.
</action>
